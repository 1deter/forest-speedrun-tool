## Build plan (forest-researcher, 2026-10-19)

### What the game gives (proved live, v0.24.374, Slot 1; docs/game-notes.md)

- **The 1-4 hotkey items** = `LocalPlayer.Inventory._quickSelectItemIds`
  (`int[4]`; <= 0 empty: `0` from Awake, `-1` after an item moved slot).
  Key i+1 equips slot i (`ItemSlot1..4`, `PlayerInventory.CheckQuickSelect`).
  Bridge: `SetItemAsQuickSlot 2` with `_combiningItemId 53` -> `[2]` = 53;
  `press ItemSlot3` -> `RightHand._itemId` 53, `press ItemSlot1` -> 80.
  Writers are array element stores (no field write to hook) and the array
  is replaced on load: **poll the 4 ints through `LocalPlayer.Inventory` on
  the state cadence (5 Hz)**, never cache the array or the component.
  Names: the existing `InventoryReader.NameForId` (as ItemCounter does).
- **Keys pressed**: Rewired has 53 actions; `Game/GameActions.Held(index,
  sign)` polls each by id with no patch and already ORs in the bridge's
  injected input and a TAS replay (bridge: `Held(5,1)` false, true under
  `hold Jump`; `Held(27,1)` true under `hold ItemSlot1`). **GameActions is
  bound only when something calls `Ensure`** - it read `not bound yet`
  with the input overlay off; the recorder must call
  `GameActions.Ensure(log)`. Do NOT record through `InputInject` /
  `TasInput` (installed only for the bridge / TAS; a second recorder there
  would fight TAS recording).
- **Values**: all 12 of the site's SHOWN preset (Health, Stamina, Energy,
  Fullness, Thirst, Armor, ColdArmor, BatteryCharge, BodyTemp, Stealth,
  Cold, IsLit) are `PlayerStats` fields, read live, so they are already
  channels of the 5 Hz `v|` track (`Game/PlayerStateReader`). Speed is in
  the `s|` samples (`ReplayStats.SpeedAt`). No new game read for (c) but
  the quick slots.

No live tuning is needed: forest-dev builds it.

### The build

1. **Recording tracks** (`Data/RunRecorder`, `Data/AttemptFormat`, tested):
   - `InputSource` (asked every frame of a running recording): fills a
     reused `bool[]` of "held" per action end, returns false when not
     ready. Recorded as changes, stamped with `Elapsed`, frame-true (a
     1-frame wheel / bridge press must survive; 30 Hz would drop it).
     Format: a header `keys|<name>|<name>|...` (the action ends: an axis
     action gives `Name+` / `Name-`, a button `Name`) and change lines
     `kc|<t>|<index>=<0|1>|...` (only the indexes that changed). Cap like
     MaxEvents (e.g. 20000 changes) so a stuck key cannot grow a file
     forever.
   - `QuickSlotSource` (on the state cadence): fills `int[4]`; recorded
     when it differs, as `qs|<t>|<id1>|<id2>|<id3>|<id4>` (ids; names
     looked up at playback with the same reader, no names in the file).
   - Add `keys` / `kc|` / `qs|` to the `StartsAt` list in
     `AttemptFormat.WithRunner` (the `runner|` line goes before tracks).
     Older readers skip unknown lines (the site links the same file).
   - Attempt: `KeyNames`, `KeyChanges`, `QuickSlots` + "held at t" and
     "slots at t" lookups (binary search, like `ReplayStats.IndexAt`).
2. **The game side** (`src/Game`): the input source in a small
   `Game/ActionRecorder` (or a method on GameActions): `Ensure`, then per
   action index `Held(i, +1)` and, for axis actions, `Held(i, -1)` into
   the reused array. No allocation; at most 106 delegate calls a frame,
   only while recording. The quick-slot source: `Game/QuickSlots.Read(int[])`
   reading `LocalPlayer.Inventory` -> `_quickSelectItemIds` through a bound
   getter (FastField), all 0 when there is no player. Wire both into
   `_recorder` beside `StateSource` / `ItemSource`, so spot runs record
   them too (the contract's (b) covers spot runs).
3. **(a) Record / Done with no spot** (`PracticeRunModule`, new partial
   `PracticeRunModule.Recordings.cs`): a second `RunRecorder` (the spot
   recorder stays untouched), `ForceStart(pos)` on Record, `Finish()` on
   Done, saved by `AttemptStore` under its own anchor folder
   (`runs/recordings/`, anchor `Recording`), never uploaded, never a run
   mode attempt. Refused while a timed run is running. A Runs-tab
   section: Record / Done (one button, label by state), the list (date,
   length), Watch, Remove (with the usual confirm), status under the
   button. A rebindable hotkey `rec.toggle` (KeyCode.None default, like
   `tas.record`). Practice labels as the other practice tools
   (`Ctx.Practice.Mark`), never gated beyond what the replay camera
   already does (rule 12). One log line per Record / Done / Watch /
   Remove (`Recording: ...`; then `scripts/log-catalogue.py` +
   docs/log-lines.md).
4. **Watching a recording** (`PracticeRunModule.Camera.cs`): today the
   camera needs `_segment` and plays `_reference`. Add a watched-run field
   (`_camRun`): Watch sets it to the recording and starts the camera with
   no segment; the spot Watch keeps `_reference`. Every `_reference` read
   in Camera / ReplayBar call sites goes through one `CamRun` getter; the
   "Compare to changed" re-sync applies only while watching `_reference`.
   No checkpoint ticks for a recording (no splits); event ticks as today.
   The same field lets the Runs tab watch the LAST run, not only the
   comparison run (author 2026-10-15 above) - a Watch on the last run's
   row is cheap to add once `_camRun` exists (builder: add it if it fits,
   else file it).
5. **(b) Keys on playback**: a key line on the replay bar ("Keys:
   Forward  Sprint  Jump", the action labels the input overlay uses -
   `Data/ActionFunctions` / `InputActionTable` names), rebuilt only when
   the held set at the playhead changes (cached; the bar refreshes at
   10 Hz). Plus, with the input overlay on, feed it: a `ReplayKeys`
   provider asked first in `GameActions.Held` / `Axis` (like the TAS
   replay branch) while the replay camera plays, and the overlay's
   "nothing while a cursor shows" rule (`InputOverlayModule` ~line 356,
   `live = editing || !Cursor.visible`) relaxed while that provider is
   active - the replay bar frees the cursor, so without this the tiles
   never show during a replay. The mouse box: from the `l|` look track's
   yaw / pitch deltas, or left still (state which).
6. **(c) Values on the bar**: `ReplayStats` grows a value list: the
   chosen channel names + `Speed` + `Quick slots`. Default ("Basic") =
   the site's SHOWN twelve + Speed + the 4 quick-slot items. Labels and
   formats as the site (app.js `SHOWN` / `fmt`: Fullness and Thirst x100
   with `%`, Battery `%`, Body temp 1 decimal + ` °C`, Cold / Light on
   yes / no, Armor -> Armour, ColdArmor -> Cold armour). The pick is a
   config string `[Runs] ReplayValues` (comma list; empty / `Basic` = the
   default), parsed in `src/Data` (tested), edited in a fold (Settings >
   Ghost and replay, or a "Values" button on the bar - builder's choice)
   listing the watched run's channels with toggles and a "Basic" reset.
   The bar's value text goes through `UiText.Draw` (it wraps; the bar
   grows); cache keyed on (run, state index, sample index, quick-slot
   index, pick version). A run without a state track keeps the T-0386
   "not recorded" wording.
