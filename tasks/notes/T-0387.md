## What was proved live (test build, Slot 1, 2026-10-16)

A throwaway `ArmsReplicaTest` MonoBehaviour (not committed) sampled the
live animator every LateUpdate and played it back 0.3-1 s late on an
`ArmsReplica`, placed 3 m in front of the player or 30 m to the side with a
picture-in-picture camera on the copy's head:

- Build: 12.5-16.9 ms once, 276 components stripped, **0 left, no Unity
  errors** (after the dependency-aware strip), 334 renderers, 16 in-body
  held models mapped. `LocalPlayer.Animator / AnimControl / ScriptSetup /
  MainCam / CamFollowHead` and the held models stayed the live player's.
- Pose: a plane-axe swing (`stickAttack`), a sprint (`axis Vertical` +
  `hold Run`) and looking down / up replayed; head joint error 0.000-0.002 m;
  a camera on the copy's head showed the arms, lighter and axe in the same
  place as the live view (shots `arms-pip-*.png`, `arms-front-*.png` in the
  bridge folder).
- Held: `SetHeld` swapped in the spear (56) and flare (43) - FakeParent'ed
  models copied under the copy's `rightHandHeld` - and hid the lighter.
- Cost: reading 6 layers + 35 floats 2.4 us a frame, no allocation;
  posing (6 Play + 35 SetFloat + Update(0)) 0.19 ms a frame.
- Data rates: layer state changes 2 in 1,551 frames (running, looking), 8
  in 1,006 (with a swing); layer-frames in transition 63 / 263; floats
  changed (> 0.01) in ~30 % of frames (vSpeed, overallSpeed, normCamX lead).

## Build plan (forest-dev)

### 1. Pure data (`src/Data`, tests)

`Data/AnimTrack.cs` (new), attached to `Attempt` as `Anim` (null = none):
- `string[] Floats` - the float parameter names, recording order.
- `int Layers`.
- Samples in flat lists, no per-sample arrays (verify: no per-frame
  allocation): `List<float> T`, `List<float> Yaw`, `List<int> Hash`,
  `List<float> Time`, `List<float> Weight` (Layers entries per sample;
  layer at weight 0 stored as hash 0, time 0, weight 0).
- `List<AnimFloat>` {T, Index, Value}: only changes (> 0.01 from the last
  written), all on the first sample.
- `List<AnimHeld>` {T, int[] Ids}: the equipment slot ids when they change
  (rare - an array per change is fine).
- `PoseAt(float t, int[] hash, float[] time, float[] weight, float[] floats, out float yaw)`
  into caller buffers: per layer, same hash in the samples around t ->
  lerp time and weight; different -> the earlier sample's state (a
  switch shows at its recorded time). Floats: lerp between the change
  points (step if no later change). `HeldAt(t)`: last change <= t.

`Data/AttemptFormat.cs`, new lines (older readers and the site skip them;
the dispatch compares `p[0]` exactly, so `a` is safe beside `anchor`):
- `anim|<layers>|<float name>|...` - header, once.
- `a|<t>|<yaw>|<hash>:<time>:<weight>|...` - one entry per layer; `-` for
  a layer at weight 0; layer 0 written without weight. Time F3 (Unity's
  cumulative normalizedTime - interpolates without wrapping), weight F2,
  yaw F1 (the player root's yaw: the body may face away from the look).
- `af|<t>|<index>=<value>|...` F3.
- `ah|<t>|<id>|<id>|...`.
- `InsertRunnerLine`'s header-end list (line ~337) gets `anim`, `a|`,
  `af|`, `ah|`.

Tests (`tests/`, pattern of the `l|` look track and `ReplayMarksTests`):
round trip of all four lines; a run without them parses with `Anim ==
null` and replays as today; `-` layers; PoseAt lerp on the same hash,
step on a change, float lerp / step, HeldAt; unknown lines still skipped.

### 2. Recording (`Data/RunRecorder` + `Game/`)

- `RunRecorder.AnimSource` (delegate like `LookSource`): asked on a 10 Hz
  cadence (`AnimInterval = 0.1f`, its own timer like `_nextStateTime`),
  fills reusable buffers; the recorder appends to the flat lists and
  diffs floats / held ids itself. 10 Hz + interpolation: measure the file
  growth per minute (verify) - estimate ~+80 KB/min on ~110 today.
- `Game/AnimReader.cs` (new): `AnimProbe.PlayerAnimator()`; float hashes
  and names cached once from `Animator.parameters` (allocates - once per
  animator instance, re-read when the instance changes after a load);
  per sample: `GetCurrentAnimatorStateInfo(i)` (fullPathHash,
  normalizedTime); if `IsInTransition(i)` and
  `GetAnimatorTransitionInfo(i).normalizedTime >= 0.5` the next state's
  (`GetNextAnimatorStateInfo`); `GetLayerWeight(i)`; `GetFloat(hash)`;
  yaw = `Ctx.Player.Transform` (the recorded position's transform)
  eulerAngles.y. Held ids: `PlayerInventory._equipmentSlotsIds` (int[5])
  through `FastField`, copied into the buffer.
- Unlike `ReadLook`, not skipped while freecam flies the view: the
  animator is the player's either way, so it records while a run runs.

### 3. Playback (`Modules/PracticeRunModule.Camera.cs` / `.Replay`)

- First person with `_reference.Anim != null`: build the replica lazily
  (`ArmsReplica.Build(Ctx.Log, out why)`) **before** `_replayCam.Begin` or
  on the first FirstPerson frame (CamOffset falls back to 0.05 m if the
  camera is already flown); `Prepare(every held id in the track)` right
  after (one hitch, not mid-replay). Build failed -> today's view + a
  status line why.
- Each tick in FirstPerson: `PoseAt(_clock.T)` -> `Place(P, yaw)` (P = the
  position track's point at t, as the ghost) -> `Pose(layer...)` per layer
  -> `SetFloat(Animator.StringToHash(name) cached, v)` -> `SetHeld` when
  HeldAt changes -> `Evaluate()` -> camera at `EyeAt(look rotation)` with
  the recorded yaw / pitch (instead of P + eye). `Show(false)` in chase /
  trajectory; `Destroy()` in `EndReplayCamera`; `!Alive` after a load ->
  rebuild on the next FirstPerson frame.
- Runs tab line: "first person: arms recorded / not recorded (older run)".
- Log lines: `Replay camera: arms ...` once per build / failure (the
  `Arms replica:` line already logs the build).

### Known gaps (say so in the docs, not blockers)

`playerAnimatorControl.LateUpdate`'s bone tweaks are not replayed (neck
pitch 5 deg/unit, torch arm, flintlock aim); the lit lighter shows unlit;
endgame cutscene clips are swapped into the shared override controller
only while the live player is there (`AnimationLoadManager`); layer
crossfades snap at their midpoint.
