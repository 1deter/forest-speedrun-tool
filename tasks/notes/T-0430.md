# T-0430 - the flaky script test

**The test:** `test_tasks.AtomicSave.test_a_reader_never_sees_a_half_written_file`.

**Cause:** on Windows `os.replace` fails with PermissionError (WinError 5) while another
process has the target open. The test's reader process re-opened `tasks.jsonl` in a busy
loop with no pause, so the file was almost always open; `atomic_write` gave up after 50
tries 20 ms apart (~1 s), and under load (pre-push, a second suite running) all 50 tries
could land while the file was open. The test then failed, and its TemporaryDirectory
cleanup failed too (WinError 32) because the reader still had the file open.

**Reproduced (2026-10-19, before the fix):** a full suite loop in a prepush-style worktree
failed 2 of 11 runs, both on this test; the Locking + AtomicSave classes alone failed 3 of 25.

**Fix:** `atomic_write` retries for a 5 s deadline (as `load` does), every 2 ms instead of
every 20 ms, so it finds the gaps a busy reader leaves; the test's reader pauses 1 ms between
loads, as any real reader does. What the test asserts is unchanged.

**After the fix:** Locking + AtomicSave 40 of 40; the full suite 20 runs in a row in a
prepush-style worktree (see the task's evidence).
