# T-0198 Raw FPS: drop ParticleCam and let the main camera draw its particles - an Experimental switch, off by default?

Running notes across sessions (docs/harness.md 11a).

## Evidence (bridge, 2026-10-19, v0.24.364, author's machine, Slot 1 surface (429.9, 78.4, -4.5), lighter held)

- `OffScreenParticleCamera` sits on `player/player_BASE/LookObject/MainCamNew`
  (also on the inactive VR eye camera - ignore it). Live: `factor` Full,
  `ParticleLayers` 2 (layer 1 TransparentFX), 2 `ShadowCastingLights`
  (Sun, Moon). MainCamNew: DeferredShading, HDR, occlusion culling on,
  `cullingMask` -134218019 (layers 1, 5, 9, 27 excluded). Component
  order: SunshinePostprocess, WaterEngine, ..., **OffScreenParticleCamera**,
  Ceto.UnderWaterPostEffect, ..., AmplifyOcclusion, PostProcessingBehaviour,
  CameraDepthFix, RaymarchedClouds.
- Mechanism, by hand: `set MainCamNew OffScreenParticleCamera.enabled false`
  + `Camera.cullingMask |= 2`. Nothing switched the component back on
  (ParticleCam 0.00 in every off window; IL: nothing else refers to the
  type). Sun shadows stayed Soft.
- Measured, 10 s `FrameTimer.Snapshot` windows alternated on / off / on /
  off: surface 6.04 / 5.62 / 6.06 / 5.73 ms a frame (ParticleCam 0.31
  +0.07 after; MainCamNew 1.65-1.72 with ParticleCam vs 1.67-1.70 drawing
  layer 1 itself) = **~0.37 ms saved**. Cave 6 (8 s windows): 4.10 vs 3.79
  = **~0.31 ms**.
- Look: the lighter flame (shots `t0198-flame-pcam` / `t0198-flame-main`)
  and a building ghost (`Ghost_Fire` instantiated in front: `t0198-ghost-pcam2`
  / `-main2`) look the same; a ghost behind the fallen log is hidden in
  both modes (`t0198-ghostbehind-pcam` / `-main2`) - no see-through
  difference. Shots in `BepInEx/config/ForestOverlay/bridge/`.
- Lesson from the test: in Cave 6 the mask was -201326883 (CaveSurfaceOff
  had cleared layer 26); assigning a whole mask undid that. **Only OR /
  AND the one bit.**

## Why it is safe (IL)

- Writers of MainCamNew's mask (`ilscan refs Camera::set_cullingMask`):
  `PlayerStats.dragAwayCutScene` saves the mask, sets `dragAwayCullingMask`
  for ~10 s, puts the saved one back; `HudGui.TogglePauseMenu` (VR only);
  the PlayMaker `SetCameraCullingMask` action (FSM use not seen). Nobody
  else. CaveSurfaceOff (ours) toggles bit 26 only.
- Sun / Moon `shadows`: written only by OffScreenParticleCamera (None
  around its render, then **Soft** every frame), SunshineCamera (saves,
  None in OnPreCull, puts back in OnPostRender), and quality settings for
  other lights. With the component off they stay at the last value, Soft.
  After a Full load the new scene's component may not have run yet, so
  write Soft to its `ShadowCastingLights` once when switching it off (the
  state it leaves every frame).
- The main camera's Sun shadows are None during its own render (Sunshine),
  so layer-1 particles get no Unity sun shadows either way.
- Known look difference by order: in the main camera, transparents draw
  before every OnRenderImage effect, so SunshinePostprocess / WaterEngine
  now apply over the particles (with ParticleCam they were drawn after
  those two, before the rest). Not visible in the shots.

## Build plan (forest-dev)

Files: `src/Game/CameraTrim.cs` (a sixth part, "EXPERIMENTAL: particles in
the main camera"), `src/Game/PerfPatches.cs` (one `Add`, Experimental,
off by default, a `Flag` and a `Note`; comment entry 23 in the header
list), `docs/log-lines.md` via `python scripts/log-catalogue.py` + Meaning
lines, `docs/game-notes.md` (the ParticleCam bullet: the switch exists).

CameraTrim:
- `ApplyParticles()`: resolve `OffScreenParticleCamera` (type),
  its `ParticleLayers` (LayerMask field) and `ShadowCastingLights`
  (Light[]) fields, and `TheForest.Utils.LocalPlayer.MainCam` (a **static
  field**, Camera). Missing -> return why. `ParticlesOn = true`.
- `TickParticles()` every frame from `Tick()` (try/catch -> release +
  off, like the others):
  - `Camera cam = (Camera)MainCam.GetValue(null)`; null -> nothing.
  - A new camera (load) or none cached: `cam.GetComponent(type)`; no
    component, or it is disabled and not by us -> refuse this camera
    (remember its instance id, one log line), as ScanSunshine does.
  - While on, each frame: `int bits = ParticleLayers.value` of the
    component; if `(cam.cullingMask & bits) != bits` -> `cam.cullingMask
    |= bits` (re-adds it after the drag-away cutscene's own mask too -
    ParticleCam draws its layers whatever the main mask is, so this is
    parity); if the component is enabled -> write `LightShadows.Soft` to
    each non-null `ShadowCastingLights[i]`, then `enabled = false`, log
    once per camera. If the game switches the component back on itself
    (not seen) -> release and leave it ("left to the game"), as the others.
- `ReleaseParticles(why)`: on the cut camera (if alive): `cullingMask &=
  ~bits`, component `enabled = true`; log one line.
- `RemoveParticles()`: `ParticlesOn = false; ReleaseParticles("switch off")`.
- Keep the camera / component / bits cached; no allocation per frame.

PerfPatches: key `ParticlesInMainCamera`, label "Particles: draw them in
the main camera", description (EXPERIMENTAL, changes the picture: the
game's separate particle camera stops; the main camera draws the flames,
sheens, building ghosts, blood, rain, waterfalls itself; they may look a
little different (drawn before the sun's light-scatter effect); saves
~0.3-0.4 ms a frame here; off = the game's own drawing), `false`,
`Experimental = true`, `Flag = "particles in main camera"`. Wording needs
no sign-off.

Tests: the decision is engine glue (no pure logic); if a helper is split
out (e.g. "bits to add / remove given mask"), a small test in
`tests/ForestOverlay.Tests`. Build + tests + `python scripts/lint.py`.
