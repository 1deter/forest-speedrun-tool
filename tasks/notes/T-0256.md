# T-0256 One place to start a timed segment - design proposal (forest-ux, 2026-10-10)

Proposal, not a review of built code. Read: the Practice tab (`PracticeModule.DrawTab`, `DrawList`, `DrawEditor`, `DrawStartState`, `Restart`, `Teleport`, `PlaceAt`), the Runs tab (`PracticeRunModule.DrawTab`, `ToggleMode`, `OnPlacedAtSpot`, `Diagnose`) on `ui-redesign` (e9a8d16; the files differ from main by a few lines, the flow is the same). Toured Practice and Runs in game on **v0.24.267 (main's release, not the branch)**: `tasks/notes/shots/2026-10-10-t0256-practice-tab.jpg`, `...-runs-tab.jpg`. No click was made (the review tools set UI fields only), so the counts below are from the code.

## What happens today (the facts the options rest on)

- Practice tab: a spot list on the left (`Go` per row = teleport only) and the selected spot's editor on the right. The **Start state** row of the editor (`Capture here`, `Delete`, `Restart (Quick)` / `Restart (Full)`) is what the author calls the savestate list on the right. **Selecting a row does not make it the current spot** - only `Go` / `Restart` do (`_current` is set in `PlaceAt` / `Restart`). F7 and the Runs tab's `Restart` act on the current spot, not the one the runner sees selected (check 21).
- Runs tab: `Practice mode` toggle (F9), `Restart` (F7, primary), `Split / finish`, `Abort`; the segment line reads "Pick a timed segment in the Practice tab" until one is armed.
- A timed run arms only while practice mode is on (`RunTiming.Source`): placing on a timed spot with it off arms nothing and says nothing on the Practice tab (`OnPlacedAtSpot` returns silently); only the Runs tab's line says "practice mode is off". Practice mode defaults to **off** (`Runs.PracticeMode`) and is kept across launches.
- Toggling practice mode on arms at once at the current spot (no restore); `Restart` restores the start state and (re)arms.
- A run spot (a category in the `Run` field) is different and stays: `Restart` there starts a run mode run (Full load, practice locked).

## Click count today (check 6 / 32; window already open on Practice)

Author's route, practice mode off (a new runner's default): 1 select the spot, 2 `Restart (Quick)` in the editor, 3 Runs tab, 4 `Practice mode`, 5 `Restart`. **5 clicks, 2 tabs** (4 if the second `Restart` is skipped: the toggle arms where the first restore left you). With practice mode already on: select + `Restart (Quick)` = 2, one tab. A new runner cannot tell which case they are in from the Practice tab. After the first start, F7 alone restarts it.

## Options

All three keep Go (teleport only), the editor's Capture / Delete / Restart buttons, F7 and F9, run spots, and the Runs tab as the place for splits, attempts and results. Nothing here is a new setting.

### A. A pinned "start strip" at the top of the Practice tab (recommended)

Where: above the list and editor, always visible, for the **selected** spot. It shows the spot's name, one primary button, and a mirror of the practice mode toggle with the run's state ("armed", "running", "idle") so the runner reads the state without leaving the tab (check 12). What one click does: the primary button = the existing `Restart` for that spot (restores its start state, Quick or Full as the spot says, goes to the spawn, **turns practice mode on if it is off**, arms). It also makes the spot the current one, so F7 and the Runs tab then agree with it. On a run spot the same button starts the run mode run (its label says so, as `StartStatus` does today: "Starting a run (Full load)..."). Old route: still works; the Runs tab keeps its own `Practice mode` / `Restart` row (a copy of the control under each, decisions.md *Easy to learn*: "or a copy of the control under each").
Clicks: **2, one tab** (select, Restart), in either practice-mode state; 1 for the next attempt, or F7. First run, check 32 "start a timed run": 5 -> 2.
Words: `Restart`, `Practice mode`, `Start state`, `Timed segment`, `Quick load` / `Full load` are existing. A "Start" label would be **new** - recommend the existing `Restart` (F7, log lines, Auto-restart all use it); the author may prefer "Start" for the first attempt.
Guidance: ux.md 6 (one place) and 12 (state visible) yes; 5 (one way to reach each option) - the editor's `Restart (Quick)` stays as the button next to Capture / Delete, the strip is the front door; one button one job - `Restart` already means "back to this spot's start", turning practice mode on is what a timed start needs anyway (author's route did it by hand). Costs: a strip's height off the list at 1366 x 768 (about 36 px).

### B. A start button on the timed rows of the list

Where: each timed row (marked `*`) gets a second small button next to `Go`. One click: select + restore + go + arm (+ practice mode on). Old route: unchanged. Clicks: **1** from the Practice tab, 2 from any other tab. Words: a new row label (`Restart` does not fit the 44 px `Go` slot; "Start" or an icon = new word, parked).
Against: the list is 250 px wide and the names already clip ("Cave 6 body slide (keyca"); a restore - which overwrites the world you are standing in - sits one finger from `Go` on a row that is clicked often (check 28 Fitts, check 15: no confirm); two buttons per row for timed spots only breaks "same control, same place" (17); no room for the practice-mode / armed state (12); a runner who selects to *edit* is not hurt, but the one-click start is also the easiest misclick. 

### C. No new control: `Restart` on a timed spot turns practice mode on itself

Where: nothing is added. `Restart (Quick/Full)` in the editor, the Runs tab's `Restart` and F7 on a timed spot switch practice mode on and arm, with a line under the click: e.g. "practice mode turned on". Old route: kept, only the silent no-arm goes. Clicks: **2, one tab** (select, `Restart (Quick)` in the editor, which sits below Name / Category / Notes / Run / Spawn / cave, so it may need a scroll at 1366 x 768). Words: none new.
Against: the front door stays buried in the editor, there is still no armed / practice mode state on the tab (12), and F9 off then F7 flips the mode back on - a global switch changed by a spot button (question 2). It is the cheapest build (a few lines in `Restart` / `OnPlacedAtSpot`) and could ship with A (A needs the same rule).

## Recommendation

**A**, built on C's rule: Restart on a timed spot arms (turning practice mode on, said under the button). A gives the one place, the shortest route (2 clicks, 1 tab), and the state on screen; it adds one strip and no setting. B is the fastest click but the riskiest button. If the author wants no new strip, C alone already cuts 5 clicks to 2 but leaves the state hidden.

Whichever is chosen, F7 / `Restart` should act on the **selected** spot when one is selected (today it acts on the last placed one - check 21).
