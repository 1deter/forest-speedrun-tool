# T-0250 Site admin: delete a category

- 2026-10-11 (cloud session, branch `cloud/site-admin`, commit 03d9862b):
  built. `DELETE /api/admin/categories/<id>` (any admin, like every
  category write; logged in Activity by the auth filter) ->
  `Categories.Delete`: the category and every row in `category_versions`
  go. **Refused (409) while any attempt names it** by id or by name (the
  same match `Official` uses; started / abandoned / finished all count) -
  message "<name> has N run(s) - a category with runs is not deleted".
  404 for an unknown id. A deleted speedrun.com category is remembered in
  `category_sync` as `deleted:<src>`, so the daily sync does not bring it
  back as a new draft (without this a delete of one of speedrun.com's
  would undo itself within a day). UI: the open category form ends with
  **Delete category** (house `confirmButton`: the second click within 4 s,
  armed label "Click again: delete it and its versions"); the server's
  refusal shows under it; refused while another editor has unsaved
  changes (it reloads the list). Docs: docs/run-mode.md *Categories* (the
  API list lives there - note: a push of that file redeploys the bot).
- Tests: `CategoryTests.Delete_TakesEveryVersion_RefusedWithRuns_SpeedrunOnesStayDeleted`
  (unit) and the API leg in `Api_AdminSaves_PluginReadsPublished` (403
  without a token, 200, gone from categories.txt and /api/categories/<id>/<v>,
  404 again). `dotnet test site/ForestSite.Tests`: 124 passed (Linux).
  Local copy in headless Chromium (desktop + 375 px): a category with an
  attempt -> "Failed: With runs has 1 run - ..." under the button; one
  without -> gone from the list. Console: only the refused DELETE's 409
  (the browser logs every failed fetch). `scripts/site-smoke.py` passed.
- Proposed CHANGELOG line (site only, no plugin release): "Site admin:

  category with runs is not deleted".
