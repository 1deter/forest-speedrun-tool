# T-0428 Quick load: an animal killed since the capture stays dead, one spawned since stays, none is moved back

Running notes across sessions (docs/harness.md 11a).

- 2026-10-18: Researched live (forest-researcher, bridge, v0.24.360, Slot 1 Creative): a kill since the capture stays dead (root inactive in the pool, zone cap lowered), its corpse is already removed (T-0411); respawn / despawn / move-back mechanisms proved over the bridge; build plan below. Game facts: docs/game-notes.md *An animal's death, spawn and pool*.

## Cause (proved live, 2026-10-18, v0.24.360, Slot 1, at (428, 78, -4))

Capture `t428a` with 5 zone rabbits (zone `AnimalForestZoneRabbitsAndLizards (9)`,
cap `MaxAnimalsTotal` 8, `SpawnedAnimals` 5, `sceneTracker.maxRabbitAmount` 12):
- `animalHealth.Hit 10` on `rabbitGo(Clone)004` -> `Dead`; root inactive (in
  `PrefabPool._despawned`), zone cap 7, one `AddSpawnBackTimes` entry,
  `maxRabbitAmount` 10, its entry still in `SpawnedAnimals`, a
  `rabbit_RAGDOLL(Clone)` root. After `restore t428a`: the ragdoll was removed
  (`removed 1 item(s) made since the capture (Rabbit Dead x1)`), the rabbit
  still inactive, cap 7, back times 1, max 10. A deer and a raccoon spawned
  and killed after the capture: ragdolls removed too (`GenericMeat x2`), their
  zone's cap lowered by 2 and not given back.
- Nothing removes an animal spawned since or moves one back (T-0425's gaps).

What a fix can do, each tried over the bridge on the released DLL:
- **Same root back**: `PrefabPool._despawned.Remove(X)` + `Insert(0, X)`, then
  `SpawnPool.Spawn(prefab)` returned X (the same instance id; without the
  move the head, another rabbit, came out). Then position, remove X from
  `zone.SpawnedAnimals` (else listed twice: 5 -> 6), then
  `AnimalSpawnController.OnSpawnedFromAssetBundle(X, zone)` (= `SetupAnimal`).
  Two rabbits brought back this way walked off, `homeState`, renderer
  visible, zone count 5.
- **Pitfall seen**: spawning without the position leaves the root at the
  prefab's spot (0, 70, 0); its old `AnimalDespawner` (Die keeps it) despawned
  it again within 1 s. Spawn with the position (the 3-argument overload) and
  set up in the same frame.
- **Spawned since**: `AnimalDespawner.UpdateSpawnState(false)` -> zone entry
  removed, root back in the pool (`IsSpawned` false), despawner destroyed.
- **Moved**: root `Transform.position` set held (settled on the ground, stayed
  3 s+); the facing is `animalAI.animatorTr`'s rotation (root rotation is
  always 0), and a yaw set there held.

## Fix (build plan, forest-dev)

Mirror rule (decisions.md, 2026-10-18): after a Quick load the zone animals
are those of the capture, where they stood, and the spawn caps as they were.
Same world and launch only (the existing `sameWorld` gate). Scope: roots with
`animalHealth` (rabbits, lizards, deer, raccoons, squirrels, boars,
tortoises: the zone animals); birds, fish and `animalController` turtles are
left (gap, see the decisions below).

### 1. Pure: `src/Data/AnimalSpawns.cs` + `tests/.../AnimalSpawnsTests.cs`
New header lines (the `animals` line stays as it is, so v0.24.358-360 still
read their part of a new file):
- `animalposes`: per live animal `id:prefab@zone@x,y,z@qx,qy,qz,qw`, joined by
  ';'. `id` the root's instance id (same key as `animals`), `prefab` the pool
  prefab's name (`SpawnPool.GetPrefab(root.transform).name`; an entry whose
  name holds ':' '@' ';' or ',' is dropped), `zone` the index in
  `AnimalSpawnController.Zones` or -1 when none (`AnimalDespawner` missing or
  its `SpawnedFromZone` null), the root's position, `animalAI.animatorTr`'s
  rotation (invariant culture, "R").
- `animalzones`: per zone `index:max@ids@backs`: `MaxAnimalsTotal`; the
  `SpawnedAnimals` entries' instance ids in order (',' joined, a null entry
  skipped); `AddSpawnBackTimes` as seconds left at the capture
  (`t - Time.time`, ',' joined, may be <= 0). Every zone (131; short).
- `animalcounts` (or a part of `animalzones`; builder's call): the
  `sceneTracker` ints `curr` Lizard / Turtle / Rabbit / Tortoise / Raccoon /
  Deer and `max` Lizard / Turtle / Rabbit / Shark / Tortoise / Raccoon / Deer,
  as `name=value` pairs.
- A pure planner: captured ids + live animals (id -> captured id, after the
  stand-in map below) -> `despawn` (live, not captured), `respawn`
  (captured, not live), `move` (both). Tests: round trip of each line,
  invariant culture under a comma culture, garbage / empty, a bad prefab name
  dropped, the planner's three lists incl. a stand-in.

### 3. `src/Game/AnimalKeeper.cs` (reflection only here)
Resolve once (missing -> one warning, that part skipped):
`AnimalSpawnController` (`Zones`; `OnSpawnedFromAssetBundle(GameObject,
AnimalSpawnZone)`, private, = `SetupAnimal`), `AnimalSpawnZone`
(`MaxAnimalsTotal`, `SpawnedAnimals`, `AddSpawnBackTimes`), `AnimalDespawner`
(`SpawnedFromZone`, `UpdateSpawnState(bool)`), `animalAI.animatorTr`,
`animalSpawnFunctions.despawn()`, `sceneTracker` (via
`TheForest.Utils.Scene.SceneTracker`), and from `PoolManager.Pools["creatures"]`
(PickupKeeper already reads `PoolManager.Pools`; share the lookup)
`SpawnPool.GetPrefab(Transform)`, `prefabPools` (name -> `PrefabPool`: its
`despawned` list, `prefab`), `Spawn(Transform, Vector3, Quaternion)` (pick
the overload by parameter types: five `Spawn`s take 3 arguments).

`Capture()` adds the poses, zones and counts (one walk; the zone controller
found once per scene, `SceneCache` if it fits).

`Restore(...)`, same world only, in this order:
1. **Despawn** each live animal not in the capture: `AnimalDespawner.
   UpdateSpawnState(false)` when it has one; else `animalSpawnFunctions.
   despawn()`.
2. **Respawn** each captured animal not live (zone >= 0 only - a zone-less
   one, e.g. a trap's rabbit, is a gap): find its root X by id in the pool's
   `prefabPools[prefab].despawned`; if there, move X to index 0. Then
   `Spawn(prefab, pos, rot)`; if the result is not X (X was culled: the pool
   made a new one) remember new id -> captured id in a static map (in
   memory, this launch, like `PickupKeeper.RemadeFrom`; drop entries whose
   object is gone) and use the map wherever live animals are matched to
   entries (the existing health step too). Then remove every
   `zone.SpawnedAnimals` entry of that root and call `SetupAnimal`, then set
   `animatorTr.rotation` (SetupAnimal randomises `GetChild(0)`'s yaw).
3. **Move back** every kept animal: root position, `animatorTr` rotation,
   `Rigidbody` velocities zeroed. (Its FSM state is left: a fleeing rabbit
   keeps fleeing from where it stood - gap.)
4. The existing **health / skin / poison** step (a brought-back animal is at
   `startHealth`, so it gets its captured health and skin here).
5. **Counters** last: per zone `MaxAnimalsTotal`; `AddSpawnBackTimes`
   cleared and refilled with `Time.time + left`, in order; `SpawnedAnimals`
   rebuilt from the captured ids, each resolved to its root (current list
   entries + live roots + the stand-in map; an id that resolves to nothing
   dropped). Then the `sceneTracker` ints.
The note grows, e.g. `| animals: 2 put back (health x1, ...), 1 brought
back, 1 removed (spawned since), 3 moved back, 2 zone(s) reset` (a pure
`Describe` in Data, with tests). No new log prefix (the restore line).

SavestateModule: pass the file's new lines; the call site stays after
`_fire.Restore` (fire is put out first).
