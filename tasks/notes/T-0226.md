- Q2: the behaviour-preserving performance patches do NOT go to Developer
  (that implies developer-only); "Debug views" is a bad name for where they
  sit - regroup features more logically in the redesign (proposal asked,
  see Round 2).
- Q3: the QA tab stays its own tab while the tool is in development;
  **remove it at the public release** (filed with T-0025 / T-0227 in mind).
- Q4: **drop the *Reload save on death* toggle.** Wider rule: settings must
  never contradict each other - where two options conflict, only one can be
  ticked (radio), or picking one disables the other. E.g. "reload the save"
  and "restart the spot" on death can never both be on.
- Q5: Info box and the legacy spot import: not ticked for removal - **keep both**.

## Round 2 answer + the build plan (2026-10-08)

Author: **Settings with folds** - "it just has to be clear and easy to navigate".

Finding: `Deaths.QuickLoadOnDeath` ("Reload save on death") defaults to TRUE
and is the fallback for Automatic / Restart / Revive when no spot applies.
So dropping it = the fallback is always "reload the save" (today's default;
`DeathPlan` state `ReloadOn = true`); "The game's own death" stays its own
choice. Only a runner who had switched the toggle off sees a change.
Run-mode `reload` lock / force are untouched.
