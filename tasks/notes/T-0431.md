# T-0431 Logs in the inventory: with logs stored, right-hand items cannot be equipped (Equip reads the real HasLogs)

Running notes across sessions (docs/harness.md 11a).

- 2026-10-19: Cause proved live 2026-10-19 (v0.24.363): the get_HasLogs prefix reaches only readers JIT-compiled after the patch; build plan in the notes file.

## Cause (proved live, forest-researcher, 2026-10-19, v0.24.363)

`LogControler.get_HasLogs` is 10 bytes of IL (`ldarg.0; ldfld _logs;
ldc.i4.0; cgt; ret`) and `get_Amount` is smaller. Unity 5.6's Mono inlines
them into a caller when **the caller** is JIT-compiled. Harmony detours the
getter's own native code, so a caller compiled **before** the patch keeps the
inlined field read and sees the real `_logs`. A caller compiled **after** the
patch calls the getter and gets the prefix's answer (MonoMod stops the
inlining once the getter is patched). So today what a reader sees depends on
whether the game already ran it in this session before the mod was switched
on.

Live test (Slot 1, (428, 78, -4), uploads off, slot backed up and restored):
`HideRightHand` and `HideAllEquiped` have the same logs branch
(`else if (Logs.HasLogs && Logs.PutDown(false, true, false)) Logs.PutDown(...)`).
1. Mod off: `Inventory.HideAllEquiped true true` (`hideOnly`, so the logs
   branch is skipped; this only JIT-compiles the method). `HideRightHand` was
   not called.
2. Mod on (`_modules[4]._logsCfg.Value true`), `Logs.Lift` x2, so `_logs` = 2.
   `Logs.get_HasLogs` by reflection returned False.
3. `Inventory.HideRightHand false` (its first run, so compiled after the
   patch): `_logs` stayed 2 and no log line.
4. `Inventory.HideAllEquiped false false` (compiled before the patch):
   `_logs` 2 -> 0, two logs dropped into the world:
   `Logs in the inventory: stored 2 -> 1 (LogControler.DMD<...PutDown> <- PlayerInventory.HideAllEquiped <- MonoMethod.InternalInvoke ...)`
   and `stored 1 -> 0 (...)`.

The same code gave opposite answers, and the only difference was when it was
compiled. `PlayerInventory.Equip(InventoryItemView, bool)` is compiled at
load, which is why T-0121 saw it refuse right-hand items with logs stored.
The same bug affects every reader the game ran before the switch-on.
Drinking water (`WaterSource` -> `HideAllEquiped`), eating, a sled, a rope
top, the glider and the rest **drop the stored logs into the world**, and
carrying them costs energy and calories. That contradicts LogStore's header
("ropes, ziplines, sitting, death etc. never drop stored logs").

## Fix (forest-dev)

`src/Game/LogStore.cs`: add a second transpiled list, `ArmsMethods`, beside
`HolderMethods`. Its transpiler rewrites
`callvirt LogControler::get_HasLogs` to a static `ArmsHasLogs(object) => false`
and `get_Amount` to `ArmsAmount(object) => 0`. Both take the instance off the
stack, as `HolderAmount` / `HolderHasLogs` do. A patched method is a fresh
DMD, so the rewrite is deterministic. Keep the getter prefixes for reflection
callers. Keep `HolderMethods` (the store) and the `AmountOfNF` / `OwnsNF`
postfixes (the store) as they are.

Notes for the build:
- `PlayerInventory.Equip` has overloads, so `GetMethod("Equip", inst)`
  throws `AmbiguousMatchException`. Patch every declared method with the
  name (or pick by parameter types). Do the same for any other name with
  overloads. Count the rewritten calls and log the total in the existing
  `on, cap N - ...` line ("N holder / repair reads redirected, M arm reads
  emptied"). A method with zero rewrites should warn, as a missing one does.
- Global-namespace types: `activateZipLine`, `mutantPickUp`,
  `playerAnimatorControl`, `PlayerHangGliderAction`, `playerCraneClimbAction`,
  `playerEnterCaveAction`, `playerZipLineAction`, `PlayerStats`. The others
  are under `TheForest.Player.Actions` / `TheForest.Items.Inventory` /
  `TheForest.Buildings.World`.
- Patching ~25 methods (with `playerAnimatorControl.Update`, a big one)
  happens once, at switch-on. Log how long `Patch()` took so a hitch shows.
- Tests: if the two tables move to a pure file under `src/Game/` (linked
  like `ModApi.cs`), test that they are disjoint, have no duplicates, and
  cover the 35 refs above except `OwnsNF` / `AmountOfNF`. Otherwise no new
  unit test, since this is reflection-only.
- Docs: game-notes.md *Logs* (the inlining fact is updated there already);
  LogStore's header; confirmed.md's "the axe equips with a full store" line
  corrected (it held only when `Equip` happened to be compiled after the
  switch-on, or with the axe already in hand).
