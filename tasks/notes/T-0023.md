## What was built

Commits on `cloud/trend-colour`:

- `07c3929` `Data/HudTrend` (pure, linked into the tests): `TrendTracker.Update(value, now)` -> Steady / Gaining / Losing.
  The rate of change per second against the last sample (the HUD's 10 Hz tick), through a **dead-band** (0.5 a
  second) and a **hold** (0.3 s): steady -> gaining / losing at once (a jump shows on the jump); back to steady only
  once no sample agreed for 0.3 s; gaining <-> losing only once the shown trend held 0.3 s. A gap over 1 s, time going
  back, NaN / infinity start over steady. `HudTrend.TryParse / Format` for `#RRGGBB` (no alpha: a see-through value
  would seem gone; parsed by hand, no allocation - Settings asks it every draw). Defaults green `#33DD55`, red
  `#FF4444`, white `#FFFFFF` (author, 2026-10-07).
- `937a46b` `HudLine.Trend`: **Speed and Total speed** offer it (the only single numbers that rise and fall - see Q2).
  `HudLayout` keeps the switch per value as a `trend` token (`ShowSpeed: trend`, or `..., after=" u/s", trend`), so it
  is in the HUD profile (T-0019); an older build ignores the token (no `=`), a value with only `trend` is kept, Attach
  keeps it, Reset layout clears it.
- `e33fb52` the runtime: `HudBuilder.Pair(label, value, number)` (RunInfo passes the speeds); one tracker per offering
  line, updated on the HUD tick only while Trend is on (reset when off); `TrendAt(slot)`. The column (`Plugin.DrawHud`)
  and a placed value (`HudWidgets.DrawWidget`) set the style's `normal.textColor` for that one draw and put it back -
  colour only, glyphs and size unchanged, so the placed values' own font texture never rebuilds for it (gotcha 107;
  `KeptGlyphs` untouched). Colours: `[HUD] TrendGaining / TrendLosing / TrendSteady` (`HudSettings`), registered as
  profile entries (in each profile file as `@HUD.TrendGaining = #33DD55`; a profile without them takes the defaults);
  parsed again only when the setting's string changes (reference compare), nothing allocates per frame. Edit HUD: a
  **Trend** toggle button on the Speed / Total speed rows, left of *Text*. Log: `HUD widget '<name>' trend colour
  on|off.`; `HUD layout reset: ... its own text and trend colour cleared.` (docs/log-lines.md regenerated, meanings
  updated).
- `e211ab5` Settings -> HUD, under the column's position, before *Values*: **Trend colours** - per trend a name, a
  16 px swatch, a `#RRGGBB` field (a valid colour is written as typed: one config / profile write per valid edit, not
  per key) and *default*; a field that is not a colour says so under it. `docs/ui-redesign.md` *HUD customiser* has a
  bullet and the layout example shows `trend`.

## Open questions (Q:)

- Q1: Are the trend colours per profile (as built: every HUD look is in the profile, and the settings registered
  there already include Compact and Text size) or one set for every profile?
- Q2: Which values offer it? Built for Speed and Total speed only. Velocity (three numbers), Position, Items, Logs,
  the run timer (always rising) were left out. Should any other value (e.g. the trajectory preview's speed) offer it?
- Q3: With Trend on, steady is the *steady* colour (white by default), not the theme's text colour - as the author's
  answer reads. Should steady instead default to "as the rest of the HUD" (the theme's text colour)?

  as well / instead?
