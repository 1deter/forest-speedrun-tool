## Fix, Part A (the contract): re-make after a Full load

All three Full loads (Restore with load, a checkpoint / start state, a
title load, a mode / difficulty mismatch) end in
`SavestateModule.AfterLoad` -> `HoldUntilLoaded`. Every runtime copy is
gone by then, so no "present" walk is needed: re-make every `p` pose.

1. **`PickupKeeper.RemakeAfterLoad(string dropped)`** (src/Game, static,
   returns a `MirrorResult` with `Remade` / `RemadeCounts` only):
   - clear `TimerCopies` / `TimerPoses` / `TimerSeen` (as MirrorRoots does);
   - prune `RemadeFrom` entries whose `Copy == null` (the load killed them);
   - `poses = DroppedPoses.Parse(dropped)`; empty -> return;
   - for each id in `DroppedPoses.ToRemake(poses, null)` (already tested
     with `null`): `RemakeCopy(p)` (try/catch, warning as in MirrorRoots),
     record `RemadeFrom[copy id] = { Copy, CapturedId }`, `NoteTimer(copy,
     p)`, count by item. Factor the loop body MirrorRoots already has
     (lines ~931-947) into one private helper both call, so the Quick load
     path's behaviour is unchanged byte for byte.
   - No world check: a Full load builds the capture's world, whatever world
     the file came from; the poses are positions, not ids.
2. **Call it** in `SavestateModule.HoldUntilLoaded`, right after
   `RemoveTakenPickups(f, false)` (after the hold: the captured scenes are
   loaded, so ground under each pose is there; the player is pinned at the
   captured spot). Only when `f.Dropped` is non-empty (a capture without
   the record re-makes nothing - the `keep`). Log one line, prefix
   unchanged: `Savestate after the load: re-made N copy(ies) the load
   cleared (Stick x1, Rock x1).` (names through `NameOfItem`), nothing when
   N is 0.
3. **Timers**: a re-made copy's `Start` must run first (it schedules its
   own fresh 60 s - re-arming in the same frame leaves two schedules;
   T-0418 notes). Start a coroutine: `yield return null` (one frame), then
   `int n = PickupKeeper.ResumeTimers(true)`, log `Savestate after the
   load: despawn timers set as at the capture N.` when N > 0. ResumeTimers
   already skips poses with no timer tag (a file before T-0418) and handles
   `s` (no timer at the capture).
4. **Docs**: docs/savestates.md, the T-0411 paragraph says "A Full load
   clears them with the scene" - add: since T-0422 the Full load makes the
   captured copies again at their poses, timers resumed, after the hold.
   Mention it in the T-0418 paragraph too (one sentence).
5. **Log catalogue**: the prefix is the existing `Savestate after the
   load`; run `python scripts/log-catalogue.py` and the lint anyway.

## Fix, Part B (needs the coordinator's / author's OK - changes the Quick load path)

Without it the chain breaks at the next restore: Full load X (copies
re-made) -> Quick load X (another world) -> the copies are removed as "made
since" and not re-made. F7 on a spot whose first restore was a Full load
(mode / difficulty mismatch) then shows them once and loses them on the
second F7 (gotcha 38: bookkeeping must survive the restores it serves).

Approach, smallest: in `MirrorRoots`, for an other-world file (threshold
0) with a `dropped` line, parse the poses in a *re-make-only* mode:
- tag each `Remade` with the file's world (the `spawned` line's world part,
  passed in), set by both RemakeAfterLoad and MirrorRoots;
- match a root to a pose **only through `RemadeFrom`** with the same world
  tag (never by its own id: ids of another launch can collide); a matched
  copy is kept and put back (not removed), its timer noted;
- the TakenList forget-loop spares a target matched that way;
- after the walk, re-make the `p` poses not matched (`ToRemake(poses,
  present)`), as the same-world path does.
A file from an older launch has no `RemadeFrom` matches, so all its copies
are removed and re-made: the same result as a Full load.
