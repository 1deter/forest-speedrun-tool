# T-0232 Discord PB webhook: post PBs from runner-made spots too

Running notes across sessions (docs/harness.md 11a).

- 2026-10-10 (cloud session, branch `cloud/pb-webhook-runner-spots`):
  built what the author decided on 2026-10-08 - an owner-only **PB posts**
  tab on /admin: *Post PBs on runners' spots* (off until saved on), *The
  same channel as community and run spot PBs* or *Their own channel* (a
  pasted Discord webhook URL). Details and tests: docs/website.md
  *Spot categories, owners deleting spots, Discord PB posts*.

## Calls made without asking (small, admin-facing; change freely)

- The settings sit in a new owner-only tab, **PB posts**, between Bot and
  Admins: the official webhook was `.env` only, so there were no webhook
  settings in the admin page to put them next to. The tab also shows
  whether FOREST_DISCORD_WEBHOOK is set (never its URL), which stays in
  `.env`.
- Owner only, like the Bot tab: the answer holds the webhook URL (a
  secret), so named admins neither see nor change it.
- Runners' spot posts have their own queue and caps (30 an hour, 5 a runner
  an hour), even in the same channel, so they never use up the community /
  run spot posts' 30 an hour.
- Only a discord.com webhook address is accepted for their own channel (no
  other host: the admin page cannot make the site call anything else).
- A runner's spot is every route that is neither a community route nor a
  run spot (a published `run =` category) - copies of another runner's spot
  included. Same rules otherwise: first run ("finished ... (their first
  run)"), new PB, not flagged, not a re-upload.

## Rework 2026-10-10 (the author's answers, T-0232)

1. The post is a Discord embed (`PbNews.Embed`), a new design - not the
   KSF post. The KSF message itself was NOT read by this session (no QA
   history tool): main compares it with the sample in the commit report.
2. A PB on a runner's spot is marked apart from a main-category PB in the
   author line, the footer and the bar colour, in the same channel and in
   a separate one.
3. First runs on a new spot post as they did ("first run").

## Words for the author (runner-facing, NOT settled)

Author line: "<runner> · new PB", "<runner> · first run", suffix " on a
runner's spot". Footer: "Main category" / "Runner's spot". Description:
"Their first run here", "<n> faster than <t>". Fields: "Category", "Rank"
("#2 of 5 runners"), "Best on this spot" ("<t> ahead of <t>" / "<t>
behind <t>"). Colours: green (main), amber (runner's spot). Open: whether
a community spot (not a published run category) is still "Main category".
