## Cause (proved live over the bridge, 2026-10-18, v0.24.353, (428, 78, -4))

**Thrown things are scene roots made by `Object.Instantiate`, and a Quick
load leaves them.** `PlayerInventory.ThrowProjectile` (molotov, flare, timed
bomb, dynamite) instantiates the held view's `_worldPrefab` (lit:
`UseAltWorldPrefab` false), and `FireRangedWeapon` the ammo prefab. All come
out at a scene root in `ForestMain_v08`, with negative instance ids lower
than the T-0411 mark, no `UniqueIdentifier`, and no `PickUp` aimed at the
root, so `RemoveSpawnedSince` skips them. Roots diffed before / after each
throw (`roots max=3000`):

| Throw | Root(s) made | Root component | Lifetime (game's own) |
|---|---|---|---|
| Lit flare (43) | `FlareSpawn(Clone)` (layer PickUp, but no PickUp) | `destroyAfter` 60 s | then `Object.Destroy` |
| Flare gun (44 + 107) | `Flare(Clone)` | `FlareWeapon` | `Invoke TurnOff` = Destroy after `Amount` s |
| Molotov, lit (71) | `Molotov(Clone)`, `SmirBroken` child with `MasterFireSpread` | `Molotov` (+ `destroyAfter` 4 s added at the break) | Destroy 4 s after the break |
| Timed bomb (29) / dynamite (175) | `Bomb_Timed(Clone)` with children `Explosion` (`Explode`), `explodeReactTrigger` (`effigyRangeDetect`) | `Bomb` (`WaitTime` 3) | `Bomb.Explode` unparents both children to the root, destroys the bomb 0.05 s later; `Explode` destroys itself after 7 s, `effigyRangeDetect` after its `destroyTime` |
| The blast | `rabbitExploded(Clone)` (gibs of a rabbit it killed) | `destroyAfter` | timed |

- **A bomb thrown after the capture explodes after the Quick load:**
  `capture t416a`, throw a timed bomb, `restore t416a` 0.2 s later.
  `Bomb_Timed(Clone)` #-189576 was still there after the restore, and 3 s
  later `Explosion` #-189606 appeared. Its id is lower than the bomb's
  because it is a child made with it. Lit flares likewise:
  `restore t416b` left both `FlareSpawn(Clone)`s burning.
- **Destroying the root cancels it:** a thrown bomb destroyed 0.5 s after
  the throw. 4 s later there was no `Explosion` and no
  `explodeReactTrigger`. Unity drops the pending `Invoke("Explode")`.
- **The molotov's fire is not a root.** `MasterFireSpread.StartFire` spawns
  `Pooling/Pool_Particles/Fire(Clone)001` (pooled, `parentFireParticle`
  false), and its `OnDestroy` despawns it. So destroying the `Molotov(Clone)`
  root takes the fire with it, the game's way. Live, the pooled fire was
  already inactive 3 s after the break.
- **A generic "every root made since the mark" rule is unsafe.** Across the
  same minutes, roots appeared that must stay: `QuickSelectViewPool`
  (-186138, a UI pool made lazily on the first equip), pooled animals
  (`lizardGo(Clone)003` plus a `currentWaypoint` root each), and held items
  that are `FakeParent` roots while unequipped (`MolotovHeld`, ...;
  `HeldItemIdentifier`, inactive). Hence the component list below.
- **Pool membership:** `PathologicalGames.SpawnPool.IsSpawned(Transform)`
  answers it (`Pool_Creatures` `IsSpawned` of a rabbit's Transform: True).
  `PoolManager.Pools` holds 11 pools. Pass `R.transform`: the pool's
  `_spawned` list holds Transforms (`Pool_Creatures`: 9, squirrels,
  rabbits and lizards).

**A copy that rolled stays rolled; one that rolled and was then taken
stays gone.**
- `FakeDrop 53` gave `Rock_Dynamic(Clone)` #-197640 at (430.11, 76.08,
  -4.12). `capture t416c`, moved it to (431, 80, -1) (it settled at (430.99,
  76.17, -1)), `restore t416c`: same handle, still at (430.99, 76.17, -1).
  Setting `Transform.position` back and zeroing `Rigidbody.velocity` /
  `angularVelocity` held it there (3 s later still (430.11, 76.08, -4.12)).
- Then rolled again and taken (`PickUp.Collect` on its `Trigger`, rock
  count 0 -> 1), `restore t416c`: the rock stayed inactive. The done line
  said `pickups put back 0`, and the 0.5 s listing still said `every world
  pickup matches the capture`. The kept entry's `Key` is item@position at
  the take (the rolled spot), and `Restore(present)` matches it against the
  capture's key (the old spot), so it never matches.

## Fix (build plan for forest-dev)

Both parts run in the one root walk of `PickupKeeper.RemoveSpawnedSince`
(rename it, e.g. `MirrorRoots`), in `SavestateBridge.RestoreInPlace`
before `LoadNow`, where it runs now.

### A. Remove transients made since the capture (part 2)

In the existing walk, a root R is also removed when all of these hold:
- `SpawnMark.IsAfter(R.GetInstanceID(), threshold)`;
- R is active, not the player's root, has no `UniqueIdentifier`, no
  `CoopAnimal`, no `HeldItemIdentifier`, no `FakeParent`;
- it is not spawned by any pool (`PoolManager.Pools` values,
  `IsSpawned(R.transform)`). Look the pools up only for such a candidate,
  once a walk;
- **R itself** (`R.GetComponent`, not children) carries one of
  `destroyAfter`, `Molotov`, `Bomb`, `Explode`, `FlareWeapon`,
  `effigyRangeDetect`. Each is a component the game already destroys R with
  a plain `Object.Destroy` on a timer, so removing it early is what the game
  does anyway.
`Object.Destroy(R)`. Count them by kind, apart from items:
`Bomb` -> "bomb", `Explode` -> "explosion", `Molotov` -> "molotov",
`FlareWeapon` / a root named `FlareSpawn*` -> "flare", else "effect".
Resolve the types in `src/Game` (game names stay there), and leave a
missing one out with a logged warning.
A threshold of 0 (another world's file) applies too. None of these survive
a save, and the pool check keeps pooled ones safe.
Done line: `..., removed N item(s) made since the capture (...)` gets a
sibling `, removed M thing(s) thrown since the capture (bomb x1, flare
x2)`. Keep the `Savestate restore` prefix and add both counts to the
`deleted + rebuilt + spawned > 0` yield.

### B. Move back copies that moved since the capture (part 1)

1. Capture (case 7, next to `CaptureSpawnMark`): walk the roots once and
   record every root item the walk would match (active, no identifier, a
   PickUp aimed at the root, not a pool's, not the player). Store its
   **GameObject** instance id, item id, position and rotation.
   `SavestateFile.Dropped` is a new header line `dropped` (written when
   non-empty, parsed, copied in `Copy()`), with
   `id:item@x,y,z@qx,qy,qz,qw;...` in invariant culture. Parse and format
   it in a pure `src/Data/DroppedPoses.cs`, with tests.
2. Restore: apply it only when `SpawnMark.Threshold(file.Spawned, world)`
   is a real same-world mark (`< 0`, not 0, not `Unknown`). Instance ids
   mean nothing in another world. Hand it over like `SpawnedThreshold`. In
   the walk, a root whose id is in the map is put back at the captured pose
   (`transform.position` and `rotation`). On its `Rigidbody`, set
   `velocity` / `angularVelocity` to zero and call `Sleep()`. Count it when
   it was more than 0.05 m or 2 degrees off.
3. Copies taken since the capture: before the walk, for each `TakenList`
   entry whose `Target` is a root with an id in the map, set the Target's
   pose the same way **and recompute `t.Key`** (`KeyFor(t.Pickup,
   t.Target)`). The completion callback's `_keeper.Restore(presentPickups)`
   then matches the capture's key and puts it back. This is the case proved
   broken above.
4. Done line: `, moved N copy(ies) back to where they lay at the capture`.
