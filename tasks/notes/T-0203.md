## Build plan (all in `src/Game/PerfPatches.cs`, one `Add(...)` each, default on)

Each `Apply` returns "" or why not (type / method / field missing ->
the switch shows the reason, game untouched), `Remove` unpatches. One
`Performance patches:` style log line per apply, as the others do.
Patch only `private`/game methods found by name + exact signature.

### 1. `OceanReuseConditionKey` - Ceto.WaveSpectrum.NewSpectrumConditionKey(int, float, float, float)

Prefix + postfix with `__instance`. Kept: the instance (reference), the
key (`object`) and its six inputs: `fourierSize`, `windSpeed`, `windDir`,
`waveAge`, `spectrumType` (read as int via FastField), `numberOfGrids`.
- Prefix: if `__instance` is the kept one, `spectrumType` is UNIFIED (0)
  or UNIFIED_PHILLIPS (2), and all six equal the kept ones with `==`
  (floats: `==`, so NaN never matches - the game's `==` would also say
  "different" for a NaN key, while a reused instance would hit the
  `ReferenceEquals` shortcut), set `__result` = kept key, return false.
- Postfix: for those two types only, keep `__result` + inputs (PHILLIPS /
  CUSTOM always run the game's code; CUSTOM can switch `spectrumType`
  inside the method - read it in the postfix, after).
- Why exact: the key's one caller (`CreateConditions`) only looks it up
  and compares it; it is never stored (a condition makes its own `Key`);
  keys are immutable. Clear the kept key on Remove.

### 2. `CaveSpawnSortNoClosure` - mutantController.sortCaveSpawnsByDistance(Transform)

Prefix returning false that does what the IL does with cached delegates:
`list.RemoveAll(s_isNull)` (`o => o == null` with UnityEngine's `==`),
`list.TrimExcess()`, then `s_target = target; try { list.Sort(s_cmp); }
finally { s_target = null; }`, where `s_cmp` is one kept
`Comparison<GameObject>` computing exactly
`(s_target.position - c1.transform.position).sqrMagnitude.CompareTo((s_target.position - c2.transform.position).sqrMagnitude)`.
`list` = the instance's `allCaveSpawns` (FastField `List<GameObject>`).
Same `List.Sort(Comparison)` call, same comparisons -> the same order
(the sort is unstable, so it must stay the same API, not `Sort(IComparer)`).
Main thread only, never re-entered (no callbacks inside the comparer).

### 3. `TerrainTextureCache` - TerrainHelper.GetProminantTextureIndex(Terrain, Vector3) (Assembly-CSharp-firstpass)

Find the type in firstpass (search loaded assemblies by name). Prefix
returning false: compute `num`, `num2` exactly as the original (position,
`terrainData.size`, `alphamapResolution`, the same casts, the same -1
for a null terrain or out of range). Then a per-cell table: `sbyte[res *
res]`, -2 = not read yet; on a miss read the cell with
`GetAlphamaps(num, num2, 1, 1)` and run the original's loop (strict `>`
from 0, first max wins, -1 if every weight is 0), store, return. The
table belongs to one `TerrainData` (reference), resolution and
`alphamapLayers`; any of them different -> rebuild (one 256 KB
pointer-free array for MainTerrain, 512 x 512). Invalidation: a postfix
on `UnityEngine.TerrainData.SetAlphamaps(int, int, float[,,])` clears
the table (nothing in the scene calls it - CraterMaker /
terraincomposer only - but a mod could). Cell 6.84 m: the player's
every-fixed-step read hits the table almost always; enemies' footsteps
share it (no thrash, unlike a last-cell cache).

### 4. `FishSpawnNoIdleCoroutine` - animalController.doSpawnCreatures

Transpiler: replace the one `ldstr "spawnFish"` + `call
MonoBehaviour::StartCoroutine(string)` with `call FishGate(MonoBehaviour,
string)` returning `Coroutine` (the following `pop` stays). FishGate
returns `self.StartCoroutine(name)` unless it can run `spawnFish`'s
first segment itself, which it does only in single player
(`BoltNetwork.isRunning` false - bolt assembly, DeathHooks shows the
lookup) and only when the segment neither spawns nor despawns:
1. `fishGo` null -> start the coroutine (the game's own error);
   `fishGo.Length == 0` (`sharkFish && isClient` is false in SP) -> null.
2. `closest = (caveFish && !SteamDSConfig.isDedicatedServer &&
   LocalPlayer.IsInCaves) ? LocalPlayer.Transform :
   getClosestPlayer(caveFish)` (private; a DynamicMethod `(object, bool)
   -> Transform` like FastField's - no `MethodInfo.Invoke`, it boxes).
3. `closest == null` (Unity `==`): `!fishSpawned` -> null; else
   start the coroutine (it despawns).
4. `fishPlayerDist = Vector3.Distance(closest.position, thisTr.position)`
   (write it).
5. `dist < fishSpawnDist`: `fishSpawned` -> null; else start the
   coroutine (it spawns; it recomputes 2 and 4, same frame, same values).
6. `dist > fishSpawnDist`: `fishSpawned` -> start the coroutine
   (despawn); else `fishSpawned = false; allFish.Clear(); totalFish = 0;`
   -> null.
7. equal -> null.
Field writes need a setter: add `FastField.InstanceSetter<T>` (a
DynamicMethod `stfld`, tested like the getters). Why exact: Unity runs a
coroutine's first segment inside `StartCoroutine`, so the gate does the
same writes at the same point of the same frame; after the final `yield
return null` nothing is left; nothing stops `spawnFish` by name
(`OnDisable`'s `StopAllCoroutines` only); `getClosestPlayer` writes only
`closestDist` / `closestPlayer`, the same values twice.
