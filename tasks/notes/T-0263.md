# T-0263 - Settings' key list and HUD values under headings; developer keys in the Developer tab

Built on `cloud/settings-sweep` (from origin/ui-redesign bdc83dd), cloud session, no game.
Author's answer (2026-10-09): (c) both - group each list under short
headings, and move the developer-only keys (dumps, type explorer, TAS, QA)
to the Developer tab. Decision recorded in docs/decisions.md *Plugin*.

## What changed
- `src/Data/KeyGroups.cs` (new, pure, tested): a hotkey's group from its id
  (exact ids, then prefixes). An id no rule knows -> *Other*, shown last in
  Settings, so a new key is never hidden.
- `src/Data/HudLines.cs`: `HeadingAt(i)` - the value list's groups, keyed
  by each group's first line's Name (a reorder cannot shift them).
- `src/Modules/SettingsModule.cs`:
  - Keys fold: Reset all keys + the status / prompt line as before, then
    the runner's keys under headings (Practice, Runs and timer, Window and
    tabs, Other if any), each group's rows in registration order.
  - `DrawDeveloperKeys(y, w)`: the developer group's rows, with the same
    rebinding, def, clash warning and messages. A message / capture prompt
    shows in the list its key is in (a dev rebind's result is under the
    Developer fold, not in Settings); the Game input status only in Settings.
  - A capture is now dropped when its row has not been drawn for 2 frames
    (tab, fold or window gone) - was "Settings tab not showing", which would
    have killed every capture started in the Developer tab.
  - HUD fold > Values: the values under headings (same bold soft style).
- `src/Modules/DeveloperModule.cs`: a *Keys* fold (last, closed by default)
  drawn by Settings.
- *Reset all keys* (Settings) still resets every key, developer keys included.

## Groups
- Practice: Save spot here (F6), Restart the selected spot (F7), Practice
  mode on / off (F9), Restart from checkpoint, Toggle freecam, Toggle
  trajectory preview.
- Runs and timer: Manual split / finish, Abort practice run, Splits: next
  comparison, Close the results panel, Replay camera, Start / stop timer,
  Reset timer, Split (free timer).
- Window and tabs: Open ForestOverlay window (F2) + every Open ... tab
  (incl. Open Developer tab).
- Developer (Developer tab > Keys): Write dump files (F11), Type explorer
  panel (F10), TAS x3, QA mark, Open QA tab.
- HUD values: Overlay (Title, Update check) / Movement (Speed .. Player
  hold warning) / Inventory and 100% (Items carried .. 100% totals) / Tools
  (Freecam, Trajectory preview, Bomb boost preview, Dump status) / Practice
  (Current spot, Practice messages) / Runs (Run timer .. Last time) /
  Always shown (ON NOW, Practice marker, Run code).

## Words (proposed - author to OK)
- Key headings: **Practice**, **Runs and timer**, **Window and tabs**,
  **Other** (only when an unknown key exists).
- Developer tab fold: **Keys**; its hover tip "The developer tools' keys:
  dumps, type explorer, TAS and QA. Click a key to rebind it (Esc cancels,
  Backspace unbinds); def puts the default back."
- HUD value headings: **Overlay**, **Movement**, **Inventory and 100%**,
  **Tools**, **Practice**, **Runs**, **Always shown**.
- Order picked for "a new runner sees what they use first": Practice,
  Runs and timer, then the window / tab openers (mostly unbound).
