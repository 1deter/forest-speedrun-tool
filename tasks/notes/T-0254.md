**Why `Check again` stays:** the task assumed the update check polls the
release asset URL. It does not: `Core/UpdateChecker.Check` reads
`https://api.github.com/repos/1deter/forest-speedrun-tool/releases/latest`
(the version, the DLL's URL and the changelog come from that JSON) - once at
startup, plus up to 15 retries a minute apart while a release is mid-publish.
A re-check when the tab opens would add api.github.com calls from every
runner's game (60 an hour per IP, shared with the author's game - rule 4), so
nothing re-asks it by itself and the button stays (a comment at the button
says so). See Q2.

No allocation added in OnGUI: every new check runs in Tick, behind a tab /
view-open edge or a time gate; a folder listing costs a `string[]` + a few
`FileInfo` every 2 s, only while that list shows. Why a poll and not
`FileSystemWatcher`: in `Data/FolderStamp`'s header.
