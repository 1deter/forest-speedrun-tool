# T-0109 Run mode: watch Time.timeScale (the debug console's _timescale / _speedyrun)

Running notes across sessions (docs/harness.md 11a).

- 2026-10-18: research (forest-researcher, v0.24.347 live): mechanism proved, build plan below - a per-frame watch of Time.timeScale (not 0 / 1 in a loaded game) and of FpCharacter.runSpeed / swimmingSpeed (above 13.5 / 3.75) during an attempt, each a run flag.

## Cause / facts (proved live 2026-10-18, v0.24.347; full text in docs/game-notes.md *timeScale*)

- Vanilla writes only **0 and 1** in play, plus **0.1 while a save loads**
  (`LoadSave.LevelSerializer_Progress`, before `Scene.FinishGameLoad` is
  true). Live: title -> Continue of Slot 1 sampled every ~0.1 s: one 0.1,
  every other sample 1. The other IL writers never run (`SlowMoButton`,
  `clscameratarget`, `SteamVR_Render`: no instance; PlayMaker `ScaleTime`:
  in no loaded FSM).
- **An external value sticks**: `set static:UnityEngine.Time timeScale 2`,
  `wait 3` -> still 2. The pause menu close and the inventory close set 1
  (live from 2 and 0.5) - so a cheat can be short; poll every frame, not
  in the once-a-second `Watch()`.
- **`_speedyrun` never touches timeScale**: `setFastRun` writes
  `FpCharacter.runSpeed = 60`, `swimmingSpeed = 20` every frame. Vanilla on
  the player: runSpeed **13.5**, swimmingSpeed **3.75** (live); runSpeed
  only ever goes down (1.2 / 0 / 1 in hit reactions, sitting, the charge
  attack - FSM values read live) and back to 13.5. The author's answer
  ("if _speedyrun also changes it, flag that too") so becomes: watch the
  two fields it writes.
- The console only exists with `Cheats.DebugConsole` on (already flagged:
  "a game cheat is on: DebugConsole"); this watch catches the same change
  made any other way (another mod, an explorer, `_eval`).

## Build plan (forest-dev)

**Scope for T-0109 (main, 2026-10-18): the timeScale watch only.** The run / swim speed parts (RunSpeedFlag, the FpCharacter reader, live check 3, the second CHANGELOG bullet) are T-0413, parked for the author - build none of them here.

1. `src/Data/SpeedCheck.cs` (pure, tested): `TimeScaleFlag(float scale)` ->
   null for exactly 0f / 1f, else `"the game's speed was changed (time
   scale " + scale.ToString("0.###", Invariant) + ")"`;
   `RunSpeedFlag(float run, float swim)` -> null unless run > 13.5 + 0.01
   or swim > 3.75 + 0.01, else `"the player's run speed was changed (run "
   + run + ", swim " + swim + "; the game's 13.5 / 3.75)"`. Constants named
   `VanillaRunSpeed` / `VanillaSwimSpeed` with a comment pointing at
   game-notes. Tests: 0, 1, 0.1 (flagged - the caller excuses loads), 2,
   0.5, 1.0001; run 13.5 / 1.2 / 0 silent, 60 flagged; swim 3.75 / 3
   silent, 20 flagged.
2. `src/Game/` reader (e.g. in `RunIntegrity` or a small `Game/SpeedRead.cs`):
   `LocalPlayer.FpCharacter` (static field) -> `FirstPersonCharacter.runSpeed`
   / `swimmingSpeed` through `FastField.Static` + `FastField.Instance<float>`
   (no boxing per frame); re-read the FpCharacter object each frame (it
   changes on a load). Missing members -> a logged warning once, watch off.
3. `RunModeModule.Tick` (per frame, after `InLoadedGame()`): only while
   `Ctx.Run.Active && _attemptOpen && loaded`, and **not** while the
   plugin itself drives timeScale - `SavestateModule.Busy` or its cutscene
   fast-forward (`FastForwardCutscene` is started fire-and-forget at
   SavestateModule.cs ~1112 / ~1665, so it can outlive `SpotRunReady`;
   expose a bool for it). First irregular value per kind per attempt ->
   `Ctx.Run.Flag(text)` (once per attempt: a bool reset in `StartAttempt`;
   a lerped value would otherwise flag every frame - Flag dedups by text
   only). `Flag` already logs `Run mode: attempt n flagged - ...`; no new
   log prefix needed.
4. Docs: docs/run-mode.md *Known gaps* - replace the "A Time.timeScale
   watch could be added" item with what is watched; docs/areas/plugin.md
   if it lists the run flags.

Not flagged on purpose: timeScale 0 (vanilla menus; a freeze outside them
stops the world and the run's real-time clock keeps counting; a bomb boost
is MoveWatch's), and walk / strafe speed (not what `_speedyrun` writes).
