## Mechanism (proved live, forest-researcher, 2026-10-19, v0.24.372)

Facts and evidence: docs/game-notes.md *Adding a binding at runtime*.
In short:
- `ControllerMap.CreateElementMap(...)` on the player's **live** Default
  map (`TheForest.Utils.Input.player.controllers.maps`, category 0) is a real
  binding. It sits beside the game's own elements, and Rewired treats it like
  them: every `GetButton*` / `GetAxis*` reader and the state switching
  (`SetMappingExclusive`). Shown with Slot 1 at (428, 78, -4), sampling the
  player's y every 0.06 s:
  - wheel up (element 2, Axis, AxisRange Positive) -> Jump: a 3 m jump.
    With the element deleted, the same notch did nothing (control).
  - J (keyboard, `ModifierKeyFlags.None`) -> Jump: jumped.
  - the back side button (element 6, Button, Full; SendInput XBUTTON1 =
    Unity `Mouse3`) -> Jump: jumped.
- **Three ways it clashes with the game** (the contract's "must not conflict"):
  1. `InputMappingIcons.RefreshMappings` (run on every input-state change)
     lets the last element per action win, so the HUD hint for Jump read
     "J" instead of "Space" (live).
  2. `InputMapping.LoadAllMaps` (opening / closing the game's Controls
     menu, `InitControllers`, a pad connecting) replaces the Default
     keyboard and mouse maps, so the added elements are gone (live). It also
     rewrites linked non-Default keyboard elements (IL).
  3. `InputMapping.SaveAllMaps` (the Controls menu's Save) would write the
     added elements into the game's PlayerPrefs. `InputMappingButton.
     GetElementMap` would list them in the Controls menu, and a rebind
     there deletes everything it listed (IL).
- No patch on `TheForest.Utils.Input` is needed (gotcha 122 does not apply),
  and nothing reaches PlayerPrefs unless the game saves (registry diffed).

## Build plan (forest-dev)

**Files**
- `src/Data/ExtraBindings.cs` (pure, tested): the config string. One entry
  is `Action[+|-]=Input`, with entries separated by `, `: e.g.
  `Jump=WheelUp, Crouch=Mouse3, Vertical-=K`.
  - Action: the Rewired action `name` (stable, not the descriptive name).
    `+` / `-` picks the side of an axis action (`+` by default).
  - Input: a `UnityEngine.KeyCode` name, or `WheelUp` / `WheelDown`.
  - To a target: a keyboard key gives (Keyboard, keyCode). `Mouse0..Mouse6`
    give (Mouse, element 3..9: Mouse0 3 left, Mouse1 4 right, Mouse2 5
    middle, Mouse3 6, Mouse4 7, ...). WheelUp / WheelDown give (Mouse,
    element 2, Axis, AxisRange Positive / Negative).
  - Parse / format round-trip; drop duplicates; skip unknown or garbage
    entries and report them (a warning line, never a throw).
- `src/Game/ExtraBindings.cs` (all Rewired names; reflection +
  Harmony). Every member it uses was confirmed live, listed in game-notes.
  - **Attach**: for each entry, resolve the action id from
    `ReInput.mapping.Actions` (`name` -> `id`). Then, for each target map
    = the player's map of the input's controller type in every category
    where the game binds that action on keyboard or mouse **except Menu
    (2) and Chat (1)**, or Default (0) when there is none, call:
    - keyboard: `CreateElementMap(int actionId, Pole, KeyCode,
      ModifierKeyFlags.None, out ActionElementMap)`
    - mouse: `CreateElementMap(int actionId, Pole, int elementId,
      ControllerElementType, AxisRange, bool invert=false, out
      ActionElementMap)`

    Then keep `(ControllerMap, elementMapId)`. Maps:
    `maps.GetMapsInCategory(type, 0, categoryId)` or `GetAllMaps(type)`
    filtered by `categoryId`. Never cache a map across a `LoadAllMaps`.
    The enums go through `Enum.Parse` on Rewired's types (`Pole`
    Positive / Negative, `ControllerElementType` Axis / Button,
    `AxisRange` Positive / Negative / Full, `ModifierKeyFlags` None).
  - **Detach**: `map.DeleteElementMap(id)` for each kept pair (skip the
    ones whose map no longer has the id), then clear the list.
  - **Scoped hide** around the game's own map work: Harmony prefix =
    Detach (depth 0 -> 1), postfix + **finalizer** = Attach (depth 1 ->
    0), nested-safe, on
    - `TheForest.Utils.InputMapping.LoadAllMaps`
    - `SaveAllMaps(bool)`
    - `ClearAllMaps`
    - `TheForest.UI.InputMappingIcons.RefreshMappings` (static)
    - `TheForest.Utils.InputMappingButton.GetElementMap(InputAction, bool)`
      (private static)

    These are big methods (no inlining risk). The detach on LoadAllMaps
    also avoids its `UpdateActionElementRelationships` rewrite.
  - **Self-heal** about every 2 s, cheap: if a kept map is no longer the
    player's map for its (type, category, layout), or no longer has its
    id, re-attach and log once. This covers `ControlMapper` or anything
    else that reloads maps without our hooks.
  - **Ensure**: the first attach once `ReInput.isReady` and
    `Input.player` is not null (title screen included).
- New module `Modules/GameControlsModule` (registered **last**, no tab,
  not `IsPracticeOnly`, no `Run.Refuse`; run mode allows it with no
  flag, author 2026-10-19). Settings draws its fold through `Host.Find`,
  as it does for paint: a `UiKit.Section` "Game controls" (the wording is
  yours). It holds:
  - the list, one row per entry: action (descriptive name, with the
    positive / negative descriptive name for an axis side) / input /
    remove;
  - "Add": an action picker over `ReInput.mapping.Actions` (axis actions
    as two entries), then a capture button: "press a key, click a mouse
    button or scroll; Esc cancels". Reuse `SettingsModule.CaptureKey`'s
    pattern: KeyDown from `Event.current`, Mouse2..6 polled with
    `Input.GetKeyDown`. The wheel comes from `EventType.ScrollWheel` (or
    `Input.mouseScrollDelta`); `Use()` it so the window does not scroll.
    Mouse0 / Mouse1 are accepted only from the frame after the capture
    was armed (the arming click must not bind itself).
  - A clash note, never a refusal: "also <game action> in the game's
    controls" (read from the live maps, not `UserData`), or "also the
    overlay's <hotkey>".
  - Saved in a ConfigEntry `[Game controls] Bindings` (a string). Write it
    once per add / remove (gotcha 60).
- Log lines (catalogue them): `Game controls: added Jump = Mouse Wheel Up
  (Default)`, `... removed ...`, `Game controls: 2 extra bindings applied`
  (the first attach and each re-heal only, never per RefreshMappings
  cycle), plus the parse warning.

**Tests**: `tests/` for `Data/ExtraBindings`. Cover parse / format round
trip, `Mouse0..6` -> 3..9, the wheel tokens, the axis suffix, duplicates,
garbage, and empty.

**Not in scope**: the input overlay's tiles (`GameActions.Table` is
the shipped defaults; an extra binding already shows through
`GameActions.Held`, which reads Rewired by id). Gamepads.

## Live check steps (forest-tester, after the release)

Before: `reg export HKCU\Software\SKS\TheForest before.reg`. Slot 1,
`tp 428 78 -4`. Sample the player's y every 0.06 s while SendInput sends
(`scripts/sendinput.py wheel 2.5 1 120 0.1` / `key`; for the side button,
an XBUTTON1 `mouse(0, 0, 1, 0x0080)` / `0x0100`).
1. Settings > Game controls: add Jump = wheel up (scroll in the capture).
   Close the window, send one notch: y rises about 3 m. The log has the
   `Game controls:` line.
2. Space still jumps.
3. Add Jump = J. Then `call static:TheForest.UI.InputMappingIcons
   RefreshMappings`; `get ... KeyboardMappings[8]` must read "Space"
   (this read "J" before the fix). J jumps.
4. `get static:TheForest.Utils.InputMapping instance`, `call <it>
   InputMapping.LoadAllMaps`: wheel and J still jump.
5. Open the game's Options > Controls: Jump still shows Space. Close it.
   `reg export` again and diff: no new `<actionId>9</actionId>` element
   with keyboardKeyCode 106 (J) or mouse element 2.
6. Wheel down / a side button (Mouse3) bound to another action (e.g.
   Crouch) works. Remove a binding: the input does nothing again.
7. Restart the game: the bindings come back from the config.
8. Run mode (a run spot's Restart, uploads off, the attempt deleted
   after): the wheel jumps and the report has no flag for it.
Clean-up: clear the bindings, restore `before.reg` if the diff showed
anything.
