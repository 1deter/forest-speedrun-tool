# T-0266 Runs tab's deleted-attempt check: a light site answer

Running notes across sessions (docs/harness.md 11a).

## 2026-10-11 - built in a cloud session (branch `cloud/light-deleted-check`)

No game, no bridge here (Linux, repo only). Same rules as T-0144: once per
session per attempt, at most 5 (RecentShown), offline / anything else
leaves it listed.

**Site** (commit 1acffa8b):
- `GET /api/attempts/exists?ids=<id>,<id>` -> `{"there":[..],"gone":[..]}`,
  nothing else about the attempts (`Attempts.Exist`, one `SELECT id ...
  WHERE id IN (...)`). Each id once, in the order asked, empty names
  skipped; an id that is not an attempt id is `gone` (as its
  `GET /api/attempts/<id>` is a 404). At most `Attempts.MaxExistIds` (20)
  ids, else 400; no ids = 400. Rate limit `read`. Never a 404.
- Its literal route wins over `/attempts/{id}` (ASP.NET literal-segment
  precedence; proven by the test). On the **old** site the same path hits
  `/attempts/{id}` with id `exists` -> 404 `no such attempt` - that is the
  plugin's fallback signal.
- Tests: `AttemptTests.StartCheckpointLog_Green_ThenImmutable` asks it
  before the owner's delete (there) and after (gone) and pins the two key
  names the plugin reads; new `ExistsCheck_NamesEachOnce_AndIsCapped`.

**Plugin** (commit c0826cc1) - small, for porting:
- `Data/SentAttempts`: `ExistsUrl(baseUrl, ids)` (ids escaped, so a broken
  sent.txt line cannot split or add a query) and `ExistsMeaning(code, body,
  asked, out oldSite)`: 200 with both lists -> There / Gone per id, an id
  in neither -> Unknown; 404 -> `oldSite`; anything else (offline, 429,
  5xx, a proxy page, a 200 without both lists) -> all Unknown. 2 new tests
  in `SentAttemptsTests`.
- `Modules/RunUploadModule.Attempts.CheckSent`: one light GET first; on
  `oldSite` it sets `_noExistsCheck` for the session, logs
  `Attempts: the site has no light attempt check yet (404) - each listed
  attempt is asked about in full this session.` and runs the T-0144 loop
  unchanged. `DropSent` takes how it learnt it: the log line is now
  `... was deleted on the site (<how>) - ...` with `<how>` = `the site's
  attempt check` or `404`. The runner-facing status line is unchanged.
- docs: `docs/run-mode.md` (the Runs tab check + the site's endpoint
  list), `docs/log-lines.md` regenerated + its Attempts meaning.
