# T-0411 Restore: remove dropped-item copies (Stick_Dynamic) made after the capture?

Running notes across sessions (docs/harness.md 11a).

- 2026-10-18: Researched live (forest-researcher, bridge, v0.24.349): cause and build plan below.

## Cause (proved live over the bridge, 2026-10-18, v0.24.349, Slot 1 world)

- A full-inventory take of a greeble stick runs `DoFakeDrop`, which returns
  false and calls `PlayerInventory.FakeDrop(57, null)`. That `Instantiate`s the
  item's pickup prefab: `Stick_Dynamic(Clone)` at a **scene root** (no
  parent), `ForestMain_v08`, no `UniqueIdentifier`. Its `Trigger` child's
  `PickUp._destroyTarget` is that root, and `_poolManagerDespawnCreature` is
  false. `FakeDrop 53 / 56 null` gives `Rock_Dynamic(Clone)` /
  `spear_Dynamic(Clone)` with the same shape. (The greeble's
  `_spawnAfterPickupPrefab` is null, so game-notes is corrected.)
- The copy is not saved, so `LoadNow` never deletes it, and the delete step
  only touches objects with identifiers. A Quick load of `t411a` after the drops left
  Rock_Dynamic and Stick_Dynamic in place (`2 world pickup(s) not at capture
  (Rock x1, Stick x1)`). Only the spear rule removed the spear. A Full load of the
  same file cleared them all (the scene reloads), so the Full load needs nothing.
- **Instance ids order creation** (the bridge's handle is `GetInstanceID`):
  scene objects are positive. Runtime-made objects are negative, and each is
  lower than everything made before it: pool greebles -4.81 M, drops after
  them -4.82 M, the player after a Full load -4.84 M (the counter keeps running
  across loads), an `Object.Instantiate` -4936210 and then the next drop
  -4936214. Capture `t411b` was taken with Rock_Dynamic -4935808 lying there.
  The drops after it were Stick -4936058 and spear -4936108, so exactly the
  ones made after the capture have lower ids.
- In a fresh world (after the Full load), the only runtime-made pickups whose
  destroy target is a scene root were those drops. The plane wreck that a
  restore re-creates has its pickups as children (`Hull(Clone)/...`).
  Sapling sticks from `ApplyCuts` are children of the cut clone. Pools keep
  theirs under `Pooling/...`.

## Fix (build plan for forest-dev)

Rule: **at a Quick load, destroy every scene-root world item made after
the capture.** That is a root `GameObject` R that is active, has
`R.GetInstanceID() < T`, has no `UniqueIdentifier` on R, is not the player's
root, and has a `PickUp` in its children whose `_destroyTarget` is R (or null
with the PickUp on R) and `_poolManagerDespawnCreature` false.
`T` is the capture's mark when the file's world is this world, else `0`
(every runtime-made root item). None of those can be in another world's file,
which matches what a Full load of that file shows.

1. `src/Data/SpawnMark.cs` (pure, tested): `Format(world, mark)` returns
   `"<world>:<mark>"`. `Threshold(string line, string currentWorld)` returns
   the mark when the world matches and it parses (a negative int), else 0.
   `IsAfter(int instanceId, int threshold)` is `instanceId < 0 &&
   instanceId < threshold` (threshold 0 means every negative id).
2. `src/Data/SavestateFile.cs`: a `Spawned` string with a header line
   `spawned` (written when non-empty, parsed, copied in `Copy()`), like `bushes`.
   Tests in `SavestateFileTests.cs`: a round trip, and absent gives "".
3. World key: reuse `NatureKeeper.World()`. Make it `internal static
   string WorldKey()` or move it to a small shared helper. It is the same
   `<launch>-<MassDestructionSaveManager id>` key that `bushes` uses.
4. Capture (`SavestateModule`, next to `p.Bushes =
   _nature.CaptureMark()`): create `new GameObject("ForestOverlay spawn
   mark")`, read its `GetInstanceID()`, then `Object.DestroyImmediate` it.
   Store `SpawnMark.Format(WorldKey(), id)` in the file. Take the mark on the
   serialization frame. A drop made by the capture's own frames (for example
   the glider) carries an identifier anyway.
5. `PickupKeeper.RemoveSpawnedSince(int threshold, Dictionary<int,int>
   counts)`: walk `SceneManager.GetSceneAt(i).GetRootGameObjects()` the way
   `ClearCorpses` does. Do **not** use `FindObjectsOfType` (20-37 ms a walk).
   Compare the id first, and only then call `GetComponentsInChildren(PickUp,
   true)` and run the checks above. `Object.Destroy(R)` and count by item id.
   Also drop (and destroy) `TakenList` entries whose target is such a root.
   That covers a copy made after the capture and then picked up again: it is
   kept hidden now and never put back.
6. Call it in `SavestateBridge.RestoreInPlace` right after the delete
   step, before `LoadNow`, so nothing this restore makes exists yet. The
   module hands the threshold over the way it hands `BlueprintsAtCapture`
   (`SpawnedThreshold`, set from `SpawnMark.Threshold(file.Spawned,
   WorldKey())`; `int.MinValue` means do nothing, for paths that should not
   remove). Include the count in the `deleted + rebuilt > 0` yield and in
   the done line: `, removed N item(s) made since the capture (Stick x1,
   Rock x1)` (item names via `PickupKeeper.NameOf`).
7. Keep the spear / limb / log rules and the `not at capture` listing.
   Spears stuck in things and limbs on bodies are not roots.
8. Tests: `tests/ForestOverlay.Tests/SpawnMarkTests.cs`: format / parse,
   another world gives 0, garbage gives 0, and the `IsAfter` edges (positive
   ids never, equal ids never). Run `python scripts/log-catalogue.py` if a new
   prefix appears (the done line keeps `Savestate restore`).

## Live check (forest-tester, after the release)

Slot 1 or 2, god mode, standing at (428, 78, -4), uploads off:
1. `call static:TheForest.Utils.LocalPlayer Inventory.FakeDrop 53 null`
   (a rock that lies there BEFORE the capture), wait 2, `capture t411`.
2. `FakeDrop 57 null`, `FakeDrop 53 null`, `FakeDrop 56 null`. Also run
   `Inventory.AddItem 57 10 true false null` and `call <a
   Pool_Greebles/Stick_High trigger> PickUp.Collect` (the full-inventory
   copy). `find _Dynamic` lists 1 + 4 copies.
3. `restore t411` (Quick): the done line has `removed 4 item(s) made
   since the capture (...)`. `find _Dynamic` shows only the first rock, with
   its handle unchanged. The greeble stick is back (`pickups put back 1`).
   The 0.5 s listing says `every world pickup matches the capture` (or has
   no Rock / Stick in it).
4. `restore t411` again at once: `removed 0` (nothing new), the first
   rock still there, and the plane wreck's pickups untouched (`find Hull`).
5. Another world: `restore t411 load` (Full), drop one copy, then Quick
   load a file captured before the Full load. The copy goes (threshold 0).
6. Delete the test `.fosave`s and turn uploads back on.

## Gaps left (decision for the author, not in this plan)

- A copy that lay there at capture and has rolled or been moved since stays
  where it is now (no identifier, not in the save). Mirroring it would need
  the capture to list root items by instance id + pose and move them back.
- Spawned things that are not world items (a lit flare, a fire from a
  molotov, a placed bomb, effects) are not covered; the plan covers only
  PickUp copies.
