# T-0066 Savestates: 'Small Rock x1 not at capture' after restores; phantom-a's 19 items after a title load

Running notes across sessions (docs/harness.md 11a).

- 2026-10-18: research done live (bridge, v0.24.346, Slot 1 Creative): three causes, build plan below

## Causes (proved live, 2026-10-18, v0.24.346, Slot 1)

1. **A Quick load of a file from another world leaves the pickups taken
   before the capture.** Placed pickups have no identifier, so every scene
   load re-creates them (game-notes *Placed pickups across a load*). A
   Full load removes them (`RemoveTakenPickups` + `RemoveLatePickups`,
   SavestateModule ~1782); a Quick load only re-enables what the keeper
   hid since the capture (`PickupKeeper.Restore`) and lists the rest.
   Evidence: took `PickUps/Pot_1_PickUP` + `PickUps/Cash (1)` (`PickUp.Collect`
   over the bridge) at the film crew camp (729, 77, 630), captured `t66a`
   (not listed), title load of Slot 1, Quick load: `5 world pickup(s) not
   at capture (Rock x2, Pot x1, Cash x1, TapeSticky x1)`, and the pot and
   the cash were back in the world (`find type PickUp radius 12`). The
   same restore in the capture's own world, before the title load, listed
   only `TapeSticky x1` (cause 2). phantom-a (captured 2026-09-25 in an
   older launch, endgame loaded): `9 world pickup(s) not at capture (bone
   x8, Booze x1)` - the bones are `Sections/UpperWalkway/Bone_PickUp` x5 +
   `Sections/Crawlspace/Props/Bone_PickUp` x3; the file lists no bone
   (178) at all while the Meds beside them are listed - taken before that
   capture, back since.
   The file already says which world it came from: `bushes = <launch>-
   <MassDestructionSaveManager id>:<seq>` (`NatureKeeper.CaptureMark`);
   the same-world restore logged no `cut again`, the other-world one
   `bushes: 1 cut again (cut at capture)`.

2. **Our streaming force-unload brings back a taken story-spot pickup.**
   A capture and a Quick load force-unload `MainSceneGreebles` +
   `MainSceneWorldStorySpots` and the game loads them again (`Load timing:
   scene 'MainSceneWorldStorySpots' loaded (additive)` right after
   `Savestate captured`). A reload re-creates the scene's pickups: took
   `WorldStorySpots/FilmCrewBase/Tape_Roll` (handle #2256308), captured -
   the tape was back at once with a new handle (#2271072); the Quick load
   then listed `TapeSticky x1`. So after any capture or Quick load,
   story-spot pickups taken before the capture are back (vanilla does the
   same on a cave trip: entering unloads both scenes, game-notes
   *Entering a cave*).

3. **`Rock` / `Small Rock` x1-2: the player's own GreebleLayer, vanilla
   noise.** `player/ControllerObjects/GreeblesRoot/Standard` GreebleLayer
   draws `SmallRock` / `Rock` / `lb_groundTarget` (the other layer
   `Stick_Greeble_01-03`); they spawn as `Pooling/Pool_PickUps/
   Rock_High(Clone)00N`. A trip of 270 m and back moved Rock_High(Clone)001
   from (727.63, 626.65) to (732.21, 624.65) and dropped the other one:
   random per spawn (game-notes *ground sticks and small rocks are
   random*). A restore's teleport re-spawns the cells, so these differ
   from the capture every time. Nothing to put back.

## Fix (SavestateModule + PickupKeeper; forest-dev)

- **A. Other-world Quick load = a Full load's pickup clean-up.** Expose
  the world test from `NatureKeeper` (e.g. `public bool FromThisWorld(string
  mark)` - the same `mark.Substring(0, colon) == World()` test `Restore`
  makes; "" / missing = another world: a file without `bushes` predates
  the mark, so it is from an older launch). In the in-place restore's
  success path (where `LogNewPickups` starts, ~1162), when the file is
  from another world and `f.Pickups` is non-empty: `RemoveTakenPickups(f,
  false)` + `StartCoroutine(RemoveLatePickups(f))` (the late passes cover
  the endgame / caves loading after the restore, as phantom-a's endgame
  did: `endgame: loaded at capture, not by the load - loading it`). Run it
  before `LogNewPickups`' listing, or the listing still names them (it
  waits 0.5 s + the plane wreck; simplest: do the first removal at the
  start of `LogNewPickups` when a flag says other-world). Same log lines
  as the Full load (`Savestate after the load: pickups - ...`) - better a
  `Savestate restore '<n>': pickups - removed n the scene load since the
  capture brought back (...)` line; the log-catalogue + `docs/log-lines.md`
  Meaning lines if a new prefix/text.
- **B. Story-spot pickups after our streaming reload.** After a capture
  (and an in-place restore) once `MainSceneWorldStorySpots` is loaded
  again (wait for `SceneManager.GetSceneByName(..).isLoaded`, timeout ~10
  s), remove the live pickups in that scene the list does not account for:
  `RemoveTakenAfterLoad(present, {"MainSceneWorldStorySpots"}, ...)` but
  **placed only** - the clone branch (`(Clone)` within 50 m, `ClearOut`)
  must not run here, it would take the GreebleLayer rocks of cause 3 and
  re-rolled zone sticks in a same-world restore; add a parameter
  (`clonesToo`) or a scene filter applied before the clone test. For the
  capture the list is the one just written (`p.Pickups`). For the
  in-place restore in the same world this is the only removal needed; in
  another world A covers it (the scene is in `ScenesIn(f.Areas)`).
- **C. Listing (`LogNewPickups`).** Leave it; after A and B what is left is
  greeble re-rolls (Rock / Small Rock / Stick). Optional: dedupe `now` by
  key as `RemoveTakenAfterLoad` does (two Cash on one 0.1 m key).
- Tests: the world-mark test is pure - move the parse to `src/Data`
  (`CaptureMark.SameWorld(mark, world)`: "" / null / no colon / other
  launch -> false; same -> true) with tests. The placed-only filter can be
  covered if `PickupMatch` gets the decision; otherwise in-game only.
- Docs: savestates.md (Quick load from another world now clears what the
  load brought back; the story-spot reload), game-notes already has the
  facts (this commit).
