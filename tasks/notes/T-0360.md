# T-0360 Sharp text everywhere in the scaled F2 window (buttons, labels, toggles, tabs, hints) - no stretched glyphs above 768p

Running notes across sessions (docs/harness.md 11a).

- 2026-10-15: author 2026-10-15 saw it again on the Map tab at the title screen (v0.24.301 + T-0332 build): every label, button, tab and the legend soft/blurred in the F2 window
- 2026-10-15: research (forest-researcher): crisp-in-place under the window matrix is impossible (4 escape routes tried live at 1920x1200, all fail); the fix is drawing the window at scale 1 in pixels behind a facade - build plan below

## Cause (proved live 2026-10-15, v0.24.309 + a probe build, 1920x1200, window k = 1.5625)

IMGUI rasterises a glyph at the style's font size and `GUI.matrix` then
stretches the quad. The window draws under `S(k)` (T-0324), so every
glyph is a 768p bitmap magnified by k (shot
`shots/2026-10-15-t0360-1200-plain-vs-crisp.png`: top = today, bottom =
the same lines drawn at the real size - clearly sharper).

The HUD's fix (`CrispText`: font x k inside a local `1/k` matrix) cannot
work inside the window, whatever the pivot, because **IMGUI clips in
pre-matrix GUI units against the intersection of every group / scroll /
window rect**: the enlarged rect is k times wider in those units, so it
is cut at 1/k of the clip (Views tab, the long description cut after
"very large or" and its 2nd line gone). Tried live, all fail:

1. Local pivot (today's CrispText): text off by the group offsets and cut.
2. Absolute pivot (`GUIClip.Unclip(Rect)` = offsets + point, unscaled):
   right place, still cut at the shrunk clip.
3. Overwriting the global `unity_GUIClipTextureMatrix` (it exists:
   `Shader.GetGlobalMatrix` read a no-clip matrix) after the local
   matrix: no effect - the native draw sets the clip itself.
4. `GUI.BeginClip(bigRect, 0, 0, resetOffset)`: false = intersected with
   the parent (same cut, offset added); true = nothing drawn.
5. `GL.modelview` changed around the draw (matrix left alone): no
   effect - the native draw re-sets the matrix per call.

Live values: inside the body group `GUIClip.topmostRect` = (242.4, 126,
744, 556) and `GUIClip.Unclip(Rect r)` = r + (242.4, 126): window units,
offsets unscaled (matches gotcha 112). `GUIUtility.pixelsPerPoint` has
no setter (native, editor HiDPI only).

So the only way to IMGUI-native crisp text in the window is to **draw
the window at matrix identity in screen pixels**, with fonts, paddings,
borders and every rect x k. Rejected alternative (deferring all text to
a top-level pass after the window, `GUIClip.Pop` / `Push` by
reflection): z-order breaks wherever something is drawn over text
(tooltips, the Edit HUD editor, overlays), button / toggle hover colours
have to be emulated, and text fields cannot be deferred.

## Build plan (forest-dev)

Modules keep laying out in window units (no constants change); one
facade converts at the IMGUI boundary.

1. **`src/Core/WinPx.cs`** (name free): `static float K` (1 outside the
   window, so every wrapper is a plain pass-through for the HUD, splits,
   results, notices); `Rect Px(Rect)` (x, y, w, h x K);
   `Vector2 Mouse` (`Event.current.mousePosition / K`); wrappers with
   GUI's exact overloads as used: `Label`, `Button`, `Box`, `TextField`,
   `TextArea`, `HorizontalSlider`, `DrawTexture`,
   `DrawTextureWithTexCoords`, `BeginGroup` / `EndGroup`,
   `BeginScrollView` (returns the scroll / K, scroll in x K) /
   `EndScrollView`, `DragWindow`; `CalcSize` / `CalcHeight` that measure
   at the px size and return units. Each wrapper with K != 1: scale the
   style around the call (fontSize -> px size, padding, border,
   overflow, contentOffset, fixedWidth / fixedHeight; put back after, as
   `CrispText.Enlarge` / `Restore` do - no allocation, no style copies).
   A style with fontSize 0 uses the skin font's size (`CrispText.BaseSize`).
   Scroll views and sliders use the skin's scrollbar / thumb / slider
   styles implicitly: scale those around `BeginScrollView` /
   `HorizontalSlider` too (else the bars draw k times thinner).
2. **Font size**: `Data/UiScale.WindowFontPx(size, k)` (pure, tested):
   recommend `Floor(size * k + 0.01)` rather than round, so text is never
   wider than the stretched text it replaces (a fixed-width single-line
   label that fit at v0.24.300 still fits; contract: nothing clipped).
   Tests: 13 @ 1.40625 -> 18, 13 @ 1.875 -> 24, 12 @ 1.40625 -> 16,
   any size @ 1 -> size.
3. **`MainWindowModule.DrawPanel`**: no `S(k)` matrix; `GUI.Window` gets
   `Px(_windowRect)` and divides the returned rect by K; the window
   style (title font, padding, border, contentOffset) scaled around the
   call. In `DrawContentsWatched`: `WinPx.K = _f` on entry, back to 1 in
   the `finally`; `CrispText.Plain` goes (in the window everything is
   already at the real size, so CrispText must see scale 1 - it does,
   the matrix is identity). `ScreenRect` stays `_windowRect * _f`.
4. **Every IMGUI call reachable from the window** goes through the
   facade: the tab strip, `DrawContents`, every module's `DrawTab` and
   its helpers, `UiKit` (Toggle's check box rect + `CheckSize`, Section
   headers, `Hint`, `DrawTip`), `UiText` (its `CrispText.Label` /
   `CalcHeight` become facade calls - at K = 1 outside the window they
   stay CrispText, so the HUD keeps its fix), `HudWidgets.DrawEditor`.
   Counts today: GUI.Button 142, Label 109, Box 28, DrawTexture 24,
   TextField 20, Begin/EndScrollView 17, HorizontalSlider 11, groups 3,
   Toggle 3 (via UiKit), TextArea 1, plus `style.CalcSize / CalcHeight`
   calls in modules. Mechanical: `GUI.X(` -> `WinPx.X(` in the window
   paths; mouse reads (`e.mousePosition` in UiKit, UiText, MapModule;
   HudWidgets' reads are HUD-space, check each) -> `WinPx.Mouse`.
5. **Map** (`MapModule` ~550): `_k = GUI.matrix.m00` and `UiKit.Unclip`
   assumed the matrix; at identity the GL origin is
   `GUIUtility.GUIToScreenPoint(Px(map).position)` and the scale K.
   `UiKit.Unclip` / the tooltip anchor: at identity GUIToScreenPoint is
   exact, so Unclip becomes `GUIToScreenPoint(Px(local))` and DrawTip
   divides by K.
6. **A lint** in `scripts/lint.py`: no `GUI.(Label|Button|Box|Toggle|
   TextField|TextArea|DrawTexture|HorizontalSlider|BeginScrollView|
   BeginGroup)(` in `src/Modules/` (allow-list the HUD-only files that
   draw under their own matrix, with a comment why) - a missed call draws
   1/k size in the wrong place.
7. Docs: gotcha 112 (already extended), docs/areas/plugin.md UI
   section: "window code draws through WinPx".

Unit tests: `WindowFontPx`, `Px` / back-conversion of a scroll offset,
the style scale / restore round trip (the shim has GUIStyle? if not,
keep it to the pure maths in `src/Data`).
