# T-0289 - Inventory tab: pin an item before it is held

Cloud session, 2026-10-11. Branch `cloud/inventory-pin` (from
origin/ui-redesign). Rides T-0025.

## What was built

- `src/Data/InventoryFilter.cs` (pure, tested): `Matches(name, filter)`
  (case ignored, no allocation per name) and `NotHeld(catalog, held,
  filter, into)` - the catalogue names matching the filter that are not
  held, each name once, names *starting* with the filter first (as
  `InventoryReader.SearchItems` ranks the item caps' search), an empty
  filter lists nothing.
- `src/Modules/InventoryModule.cs`: with text in the Filter box the list
  shows the held matches as before, then the game's items not held that
  match, greyed (`UiKit.DimColour`, follows a theme switch) as
  `Name   x0   (id N)` - the held row's format. A click pins / unpins
  one like any row (the `*` mark shows on it too).
- Pins now keep the game's spelling (`Rope`, not `rope`): a pin made before
  pickup reads `  Rope x0` on the HUD. Matching stays case-ignored.
- Item names come from what the plugin already reads: the reader's
  catalogue (`InventoryReader.Catalog`, built from `ItemDatabase.Items`
  / `_id` / `_name`, the same list the item caps' Find search uses). **No
  new game member** was needed.
- While "hide phantoms" is on, catalogue ids outside the inventory's real
  range (`InventoryReader.IsRealItem`) are not offered: `Refresh` drops
  them from the held list, so a pin on one would read x0 for good.
- `docs/quality.md`: `InventoryFilter` added to the Information tabs row's
  Paths (the lint requires it).
