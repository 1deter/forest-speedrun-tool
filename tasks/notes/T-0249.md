# T-0249 - where the usage went (measured 2026-10-09)

Source: Claude Code's local transcripts for this repo (main sessions +
subagents, 2026-10-05..09); cloud sessions are not on this machine and are
NOT in these numbers. Cost weight = input 1, cache write 1.25, cache read
0.1, output 5 (relative API prices; plan usage tracks the same shape).
Script: the session's scratchpad `usage.py` / `ctx.py` (agent-cost.py does
the subagent half).

Plan: **Pro**. Context window 1M, auto-compact at 97 % - so a session is
never compacted before ~970k.

## Totals (114M weighted, 138 transcripts)

| Who | Runs | Share |
|---|---|---|
| main sessions | 44 | 68.5 % |
| forest-researcher (Opus) | 8 | 20.6 % |
| forest-checker | 53 | 3.7 % |
| forest-tester | 15 | 2.7 % |
| everything else | 18 | 4.5 % |

Cost parts: **cache reads 74 %**, cache writes 17 %, output 10 %. Cost is
driven by how big the context is on every call, not by what is written.

## Findings

1. **The night orchestrator grew to 541k** (2026-10-07 20:40 -> 10-08 12:29,
   459 calls, median context 323k, 353 calls over 200k): 17.3M alone, 15 %
   of four days. One main session holding 20 loop rounds; nothing ever
   compacts it (97 % of 1M).
2. **Researchers on Opus: 8 runs = 23.5M (20.6 %)**, all in that night;
   each 54-196 calls, contexts to 245-386k (IL dumps, bridge replies kept in
   context). ~3M per run vs checker ~0.08M per run.
3. **Cold start: ~72k per main session** (system tools 35k, MCP tools 18k,
   memory files 8k, skills 7k, system prompt 5k; subagents 22k). Every call
   of every main session pays it; 44 sessions.
4. Day sessions sit at median 130-190k; fine, but each one is mostly the
   cold start plus QA / session-start reads.
5. **Cloud sessions (~40 overnight) are invisible here** and share the
   account's limit; each starts at >=70k and runs its own task - very
   likely a large part of the drain on a Pro plan.
6. Checker / tester are cheap (6.4 % together for 68 runs) - the rigor is
   not what costs.
