## What each item checks

- **1** - `Game/AnimReset.Cancel` crossfades an attacking arms layer to the
  learned rest (v0.24.31-0.24.32). A neck view would mean the game's
  `resetTrigger` path ran (nothing learned yet, e.g. F7 right after a
  load) - ask how soon after loading it was.
- **2** - the windup is tagged `held`; v0.24.33 cuts any arms state off the
  learned rest. A swing that plays out = the reset missed it; the log
  line then has no `ended attack state`.
- **3** - v0.24.34 sends the controlFSM `toReset2`. An eaten click = the
  FSM stayed in `stickAttack` (3 s `Wait`).
- **4** - the smash is the full-body layer (`axeAttackGround1`); the body
  seen when looking down is normal (author, 2026-09-24).
- **5** - every restart ends in `PracticeModule.PlaceAt`, which calls
  `AnimReset.Cancel` (Quick and Full load alike; a Quick load also calls
  it before the restore). After a Full load the player's animator is a new
  object, so nothing is learned yet and Cancel takes the game's reset
  path (`resetTrigger`, cleared 2 frames later) - harmless while idle, but
  a swing started during the load's hold is not cut the learned way.
- **6** - Cancel's result is appended to the `Teleport to '<spot>': ...`
  log line (from `PlaceAt`), and for a Quick load also to the restore's
  own line (`SavestateModule`). `ended attack state '<state>'` appears
  only when a cut happened with the FSM off `waitForInput`. Not yet seen
  in a real log - confirm the wording.
- **7** - `Data/PageGrouping.cs` page names are unverified (*Open threads*).
- **8** - performance reports: read `Perf (30 s):` / `Slow tick:` before
  changing anything.
