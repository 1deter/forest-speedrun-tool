# Tom's reports - fixes in v0.24.123, 2026-09-26

Posted in #general as a reply to the author's forward of Tom's reports:
https://discord.com/channels/1553092607134011542/1553092608509874318/1553503369904132220
(not in `qa/*.txt` - add it to the QA tab with a later release if wanted).

What each item checks:
1. `Game/PanelKeeper` (v0.24.123): a panel broken, rebuilt by a Quick load
   and broken again still breaks - the copy is taken once per panel and a
   copy without its pieces is never put back. Confirmed here over the
   bridge (Tom's start state, axe swings); the runner's check is the real
   hit / swing path in their own cave.
2. `Game/MenuClose`: Restart closes the pause menu (options / graphics
   screens are its children) and the inventory first, so the Quick load
   does not wait on timeScale 0. Confirmed here for the pause menu and
   the inventory; the Options -> Graphics screen is checked by the runner.
3. `GameBridge.CaveBlack`: a Go / F7 / restore into a cave switches the
   cave mouths' black backings off (and back on when teleporting out).
   Confirmed by the objects' flags here; the runner's eyes check the look.
4. `Game/PlayerHold`: the `Savestate after the load: player 3 s after in
   game - ...` line, for Tom's "could not move after a Full load" (not
   reproduced here).

```
1) A cave with wooden panels: spot with a start state before them, break a panel, F7, break it again. It should break every time.
2) Open the ESC menu (also try Options -> Graphics, and the inventory), press F7. The menu should close and the restart finish at once.
3) From outside, Go (or F7) to a spot just inside a cave entrance, then look back out: no black wall in the mouth.
4) Full load a spot a few times (Start state row set to Full load). If you ever can't move after one, Mark it and send the report.
```
